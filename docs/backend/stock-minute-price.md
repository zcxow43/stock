# 分 K 隨選抓取與查詢 API

提供使用者點選日 K 圖上某一交易日後的分鐘級走勢圖資料，採「隨點選隨抓取、抓過即永久保存」的策略，而非像日線一樣由排程主動全市場抓取。查詢時系統會先判斷是否已有可用資料，只有在必要時才即時向外部資料源請求並直接寫入資料庫，寫入後立即生效、不經任何審核流程。分鐘資料源存在「僅提供最近 30 天」的天生限制，超出範圍一律誠實回報「無法取得」，而非偽裝成暫時性錯誤；只要曾在 30 天內成功抓取並存入的日期，之後即可永久查詢。

## 欄位定義

**分鐘 K 棒**

| Field | Type/Role | Rule |
|---|---|---|
| stockId / tradeDate / barTime | 識別鍵 | 決定唯一一根分鐘 K 棒 |
| open / high / low / close | 價格 | 任一為空值代表該分鐘無成交，整根 K 棒直接捨棄，不得補零或沿用前一根收盤價 |
| volume | 成交量 | 單根分鐘的成交量增量，非累計值 |

**抓取狀態**

| Field | Type/Role | Rule |
|---|---|---|
| stockId / tradeDate | 識別鍵 | 決定唯一一筆抓取狀態 |
| status | 狀態 | 有資料／無成交資料／超出可取得時間窗／非交易日／抓取失敗，五種狀態互斥 |
| fetchedAt | 時間戳 | 上次成功抓取時間，用於判斷當日資料是否需要重抓 |
| attemptCount | 計數 | 失敗重試次數，達預設上限（3 次）後不再自動重試 |
| lastError | 說明 | 抓取失敗原因，供前端顯示 |

## 限制條件

- 分鐘 K 棒僅保留 09:00–13:30 盤中時段，時段外的資料一律丟棄。
- 任一價格欄位為空值的分鐘整根丟棄，資料表中不應存在任何價格為 0 的列。
- 超出來源提供的最近 30 天時間窗時，本地即可判定，不會對外送出注定失敗的請求。
- 已標記為失敗且達重試上限的日期，不再自動重試，僅能由呼叫端主動要求強制重抓。
- 5 分／15 分等週期資料一律由已存的 1 分 K 在查詢當下即時聚合而成，不另外落地儲存。
- 當日資料在收盤定案時間（14:00）之前會被視為未定案，重複查詢仍會觸發重新抓取；之後才視為當日已收盤定案。

## 跨主題規則

- 是否為交易日的判斷依據每日行情資料，而該資料由每日排程抓取維護（見 stock-price-ingestion.md）。
- 對外部資料源的請求節流與重試退避機制，直接沿用既有的日線抓取機制，不另建一套（見 stock-price-ingestion.md）。
- 股票代號是否存在，須先對照股票主檔確認，該主檔由每日排程抓取維護（見 stock-price-ingestion.md）。

## API 清單
| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| GET | /api/stocks/{stockId}/minute-bars | 查詢指定股票某交易日的分鐘 K 棒（必要時即時抓取並快取） | Direct（查詢觸發即時抓取與寫入，無需送審） |
