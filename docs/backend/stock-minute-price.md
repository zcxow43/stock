# 分 K 隨選抓取與查詢 API

這支 API 讓前端在使用者點開日 K 圖上某一天時，查得該檔股票、該交易日的分鐘走勢圖。查詢本身就是資料取得的觸發點：第一次被查到某個「股票 × 交易日」組合時，系統才會即時向外部資料源抓取並永久存檔，之後同一組合的查詢一律直接讀已存資料，不再對外請求。資料源依日期分兩段——近 30 天內用 Yahoo，30 天以前改用富果 Fugle，更早於資料可得起始日的一律誠實回報「超出範圍」，兩個資料源之間不互相補位。查詢一律回傳目前生效（已存或當次抓到）的資料，沒有送審機制，也沒有「異動」的概念，只有「有沒有資料」與「抓取是否成功」。

## 欄位定義

**查詢參數**

| Field | Type/Role | Rule |
|---|---|---|
| `stockId`（路徑參數） | 股票代號，必填 | 必須存在於股票主檔，否則視為股票不存在 |
| `tradeDate` | 查詢參數，日期，必填 | 必須是合法日期格式，且不可晚於今日 |
| `interval` | 查詢參數，整數，選填 | 預設 `1`，僅允許 `1`／`5`／`15`／`30`／`60` 分鐘週期，其餘一律視為不合法 |
| `refresh` | 查詢參數，布林，選填 | 預設 `false`；設為 `true` 時忽略既有快取與重試次數上限，強制重新向來源抓取 |

**查詢回應**

| Field | Type/Role | Rule |
|---|---|---|
| `stockId` / `stockName` | 股票代號／名稱 | 取自股票主檔目前資料 |
| `tradeDate` | 查詢的交易日 | 原樣回傳查詢條件 |
| `interval` | 週期分鐘數 | 原樣回傳查詢條件 |
| `dataStatus` | 資料狀態列舉：`AVAILABLE`／`NO_DATA`／`OUT_OF_WINDOW`／`NOT_A_TRADING_DAY`／`FETCH_FAILED` | 反映該日分 K 目前可否取得；「取不到資料」是本功能常態，一律以此欄位表達，不用錯誤碼 |
| `source` | 資料來源：`YAHOO` 或 `FUGLE` | 尚未成功抓取過時為 `null` |
| `availableFrom` | 分 K 資料可得的最早日期 | 每筆回應都必帶，來自設定值（預設 `2023-05-23`），與查詢日期及狀態無關，供前端顯示「超出範圍」說明 |
| `fetchedAt` | 最近一次成功抓取的時間 | 尚未抓取成功時為 `null` |
| `barCount` | 本次回應中 `bars` 的實際筆數 | 為聚合後（依 `interval`）的長度，不是資料庫中 1 分 K 的原始根數 |
| `dailySummary` | 該日日線摘要（開高低收量） | 只要該日是交易日就必回傳，即使分 K 取不到；非交易日時為 `null` |
| `bars[]` | 分鐘 K 棒陣列 | `AVAILABLE` 時有內容，其餘狀態皆為空陣列 |
| `message` | 失敗原因說明 | 僅 `dataStatus` 為 `FETCH_FAILED` 時出現，內容為抓取失敗紀錄的錯誤訊息 |

**分鐘 K 棒資料（`stock_minute_price`）**

| Field | Type/Role | Rule |
|---|---|---|
| `barTime` | K 棒起始時間，`HH:MM` | 一律以 Asia/Taipei 當地時間表示；正常交易日僅落在 09:00–13:24、13:30 這些格線上（13:25–13:29 無 K 棒），共 266 根 |
| `open` / `high` / `low` / `close` | 開高低收價，2 位小數 | 任一為空值時整根丟棄，不得補零或沿用前一根收盤價 |
| `volume` | 成交量，整數 | 為該根單獨的成交量，不是累計值；若來源為累計值需先轉換為單根增量 |

**抓取狀態紀錄（`stock_minute_fetch_status`）**

| Field | Type/Role | Rule |
|---|---|---|
| 狀態 | 狀態列舉：`AVAILABLE`／`NO_DATA`／`OUT_OF_WINDOW`／`NOT_A_TRADING_DAY`／`FAILED` | 對外序列化時 `FAILED` 顯示為 `FETCH_FAILED`，其餘四者同名 |
| 來源 | 實際抓取來源 | `YAHOO` 或 `FUGLE` |
| 抓取時間 | 最近一次成功抓取時間 | 用於判斷當日資料是否已「收盤定案」（14:00 後不再重抓） |
| 已重試次數 | 累計失敗嘗試次數 | 每次抓取失敗即累加；達預設上限（3）後不再自動重試，僅 `refresh=true` 可強制重試 |
| 最近失敗原因 | 最近一次失敗原因 | 供 `message` 欄位顯示；不得含富果 API 金鑰內容 |

## 限制條件

- 兩個資料來源（Yahoo、富果）互不備援：任一來源失敗只記錄失敗，不會改問另一個來源。
- 早於 `availableFrom` 的交易日一律直接回「超出範圍」，不對任何來源發出請求，且此限制無法用強制重抓繞過。
- 已成功抓取並存入的分 K 永久保留：Yahoo 抓到的近期資料，超過 30 天視窗後仍直接讀資料庫，不會改由富果重抓。
- 富果 API 金鑰只能來自環境變數，不得寫入版控設定檔，也不得出現在日誌、錯誤訊息或任何回應內容中。
- 未設定富果金鑰時，30 天以前日期的查詢不發出請求、不寫入抓取狀態紀錄，直接回覆設定問題造成的失敗；待金鑰補上後，同一日期不受先前失敗影響，可正常重新抓取。
- 抓取失敗達重試上限後不再自動重試，只有明確要求強制重新抓取（`refresh=true`）才能繞過上限。
- 分鐘 K 棒寫入與抓取狀態更新必須同時成功或同時失敗，不會出現「狀態已更新為有資料，但實際查無 K 棒」的不一致情形。
- 5 分／15 分等週期 K 棒僅於查詢當下即時聚合顯示，不另外落地存成新的資料列。

## 跨主題規則

- 查詢前須先確認 `stockId` 存在於股票主檔，不存在則視為股票不存在（見 stock-catalog.md）。
- 用日線資料判斷目標日是否為交易日，並以日線的開高低收量組出回應中的每日摘要；即使分 K 取不到，只要該日有日線就仍需回傳此摘要（見 stock-price-ingestion.md）。
- 富果與 Yahoo 的請求節流沿用既有的「逐來源請求間隔＋指數退避」機制，富果視為其中獨立的一個來源，各自計算間隔，不另外設計一套節流邏輯（見 stock-price-ingestion.md）。
