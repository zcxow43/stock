# 產業別漲幅排行 API

此 API 在既有的每日收盤價與產業別對應關係上，即時計算每檔股票在指定期間內的漲幅，篩出達到門檻的股票，並依所屬產業別分組回傳，每個產業別區塊並附上一個「命中股票平均漲幅」的彙總值，可依命中檔數或依平均漲幅排序區塊之間的先後。此模組只讀不寫，查詢結果完全由使用者送入的期間與門檻參數即時算出，不落地任何結果表，換一組參數即是另一份答案。回應內容純粹是漲幅統計，不涉及、也不得暗示任何買賣操作的建議。

## 欄位定義

**請求參數**

| Field | Type/Role | Rule |
|---|---|---|
| `metric` | 必填，度量方式 | `SUM`（期間漲跌幅加總）或 `AVERAGE`（加總後除以該檔期間交易日數） |
| `mode` | 必填，期間模式 | `DAYS`（近 N 交易日）或 `WEEKS`（指定週），兩者互斥 |
| `days` | `mode=DAYS` 時必填 | 1–120，取資料庫中最新的 N 個相異交易日；`mode=WEEKS` 時此參數被忽略、不報錯 |
| `startDate` / `endDate` | `mode=WEEKS` 時必填 | 前端已將勾選的自然週折算為區間起訖日；`mode=DAYS` 時此二參數被忽略、不報錯 |
| `minGain` | 選填，漲幅門檻（百分比） | 預設 `5`；範圍 `-100` ~ `1000`，允許負值與 0 |
| `commonStocksOnly` | 選填，是否限普通股 | 預設 `true`（省略即視為 `true`）；只計入代號恰為 4 位數字且首字元非 `0` 的普通股，排除 ETF、特別股、TDR，判斷方式全系統共用同一套定義 |
| `sort` | 選填，產業別區塊排序方式 | 預設 `MATCH_COUNT`；可選 `MATCH_COUNT`（依命中檔數）或 `AVG_GAIN`（依平均漲幅），僅決定產業別區塊之間的先後，不影響區塊內股票順序 |

**回應（頂層）**

| Field | Type/Role | Rule |
|---|---|---|
| `metric` / `mode` / `sort` | 回傳值 | 原樣回傳本次請求實際採用的值 |
| `startDate` / `endDate` | 回傳值（日期） | 實際採用的區間起訖日；區間內完全無交易日時皆為 `null` |
| `tradingDays` | 回傳值（整數） | 區間內全市場相異交易日數 |
| `minGain` | 回傳值（百分比，2 位小數） | 實際採用的門檻 |
| `scannedStocks` | 回傳值（整數） | 母體檔數（在市股票總數，依 `commonStocksOnly` 決定範圍） |
| `matchedStockCount` | 回傳值（整數） | 去重後的命中檔數，一檔股票只算一次 |
| `insufficientDataCount` | 回傳值（整數） | 因資料不足而未參與計算的檔數 |
| `industries` | 回傳值（陣列） | 依產業別分組的命中股票清單，僅含至少一檔命中的產業別；「未分類」永遠排在最後 |

**回應（`industries[]`，產業別區塊）**

| Field | Type/Role | Rule |
|---|---|---|
| `industryId` | 產業別代碼 | `null` 代表「未分類」區塊 |
| `industryName` | 產業別名稱 | 「未分類」固定顯示此名稱 |
| `matchedCount` | 該產業別命中檔數 | 等於該區塊 `items` 長度；多產業別會使各區塊加總大於去重後的 `matchedStockCount` |
| `avgGain` | 該區塊命中股票的平均漲幅（2 位小數） | 母體僅限該區塊列出的命中股票，必然 ≥ `minGain`；不代表該產業整體表現 |
| `items` | 該區塊的命中股票清單 | 依 `gain` 由大到小排序，同值依股票代號升冪；不受 `sort` 影響 |

**回應（`items[]`，命中股票明細）**

| Field | Type/Role | Rule |
|---|---|---|
| `stockId` / `stockName` | 股票代號／名稱 | 對應命中的股票 |
| `gain` | 期間漲幅（2 位小數） | 依 `metric` 決定為累計值或每日平均值，即用於門檻比較的同一個值 |
| `tradingDays` | 該檔在期間內實際有行情的交易日數 | 可能小於回應層級的 `tradingDays`（因停牌） |
| `startClose` / `endClose` | 期間內第一個／最後一個有行情交易日的收盤價（2 位小數） | 僅供對照參考，不參與門檻判定；不等同「複利報酬」概念 |
| `firstTradeDate` / `lastTradeDate` | 對應上述兩收盤價的日期 | — |

## 限制條件

- 母體固定為「在市股票」全部標的，無指定股票的參數；`commonStocksOnly` 只影響是否排除 ETF／特別股／TDR，不改變此本質。
- 期間前置資料不足（區間開始前沒有任何收盤價）、期間內完全無行情，或收盤價為 `0`（無法計算漲跌幅）的股票，一律計入「資料不足」，不列入結果、也不視為未達門檻，二者對使用者是不同訊息。
- 門檻比較以四捨五入至小數點後 2 位之後的值進行，與畫面顯示的值是同一個數，避免出現「顯示達標卻沒被列出」的落差。
- 一檔股票可能屬於多個產業別，命中時會在每一個所屬產業別下各出現一次；因此各產業命中檔數加總會大於去重後的命中檔數，兩個數字須同時提供、不可互相取代。
- 沒有任何產業別關聯的命中股票歸入固定的「未分類」區塊，不得被丟棄。
- 沒有命中股票的產業別不出現在回應中。
- 產業別彙總值 `avgGain` 的統計母體僅限該區塊已列出的命中股票，不含同產業未達門檻或資料不足的股票；其計算是以各檔已四捨五入至 2 位小數的漲幅相加後再平均、再四捨五入，而非以未捨入的原始值平均。
- 產業別區塊之間的排序由 `sort` 決定（依命中檔數或依平均漲幅），但只排區塊順序，不影響區塊內股票的排序；「未分類」永遠排在最後，不參與任何一種排序。
- 行情與產業別關聯的讀取一律採批次查詢，查詢次數為固定值，不隨母體股票檔數增加。
- 回應欄位、說明文字與任何產出文件一律以「漲幅／命中／統計」表述，不得出現「建議買進」「推薦」「可進場」等暗示買賣操作的措辭。

## 跨主題規則

- 漲跌幅計算所用的收盤價一律取原始成交價（未經除權息還原），與策略掃描、指標統計採同一份未還原資料，不得只在本模組另做還原，避免同一檔股票在不同分頁顯示互相矛盾的漲跌（見 stock-price-ingestion.md、strategy-scan.md、stock-indicator-statistics.md）。
- 「前一個有行情的交易日」一律以相鄰交易日認定，不因停牌造成的日曆間隔做插補，與策略掃描、指標統計採同一條規則（見 strategy-scan.md、stock-indicator-statistics.md）。
- `commonStocksOnly` 的普通股判斷沿用「只收普通股」的既有定義，全系統共用同一份，不另立第二套代號篩選邏輯（見 stock-universe-import.md）。
- 產業別分組所依據的股票與產業別對應關係，來自股票清單更新時一併帶入的交易所官方產業別；命中股票若尚無對應關係，會落入「未分類」區塊而非視為錯誤（見 stock-universe-import.md）。
- 母體股票清單（在市股票）的取得與「查詢次數固定、不隨檔數增加」的批次作法，沿用策略掃描已建立的模式，不另立一套（見 strategy-scan.md、stock-catalog.md）。
- 「回應僅表述漲幅統計、不得暗示買賣操作」的用語契約與策略掃描相同，非本模組獨有的文字風格（見 strategy-scan.md）。
