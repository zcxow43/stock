# 股票行情抓取與回補 API

本功能負責把外部股票行情寫入系統，作為指標運算、型態掃描等其他功能唯一的資料來源，所有查詢一律讀取本功能寫入後的目前資料。它提供三種抓取路徑：「每日增量」於每個交易日收盤後例行更新全市場當日行情；「全市場回補」用於系統初次建置或補齊歷史區間，主要作法是向交易所逐日取得當日全市場快照（一個交易日一次請求），只有在該來源被封鎖時才降級為逐檔查詢；「指定多檔回補」則固定以逐檔查詢（主要來源優先、備援來源接手）補特定標的的歷史。所有寫入行情的路徑（含每日增量）都必須同步推進每檔股票的同步進度，避免同一批標的被重複判定為落後而重抓。整體上這是一個立即寫入正式資料的資料擷取功能，沒有送審機制；系統啟動時也會自動觸發一次全市場補齊，讓資料庫在無人操作的情況下自行補到最新。

## 欄位定義

### 股票主檔

| Field | Type/Role | Rule |
|---|---|---|
| 證券代號 | 識別碼 | 由抓取來源回傳的股票代號，作為主檔唯一識別 |
| 中文名稱 | 基本資料 | 每次同步以來源回傳值更新為最新名稱 |
| 上市／上櫃別 | 分類 | 上市（TSE）／上櫃（OTC）；本功能的自動主檔同步僅維護上市 |
| 是否在市 | 狀態 | 是否納入例行同步母體；本功能的抓取流程不會刪除或停用既有股票 |

### 日線價格

| Field | Type/Role | Rule |
|---|---|---|
| 交易日期 | 識別鍵之一（與股票代號組合） | 台北日曆日；停牌或無交易日不產生任何列 |
| 開高低收 | 行情數值 | 一律為未經除權息還原的原始成交價；各來源之間數值一致，無斷層 |
| 成交量 | 行情數值 | 交易所快照為完整口徑，逐檔主要來源系統性偏低；以資料來源欄位辨識口徑 |
| 成交金額／成交筆數 | 行情數值 | 交易所快照與備援逐檔來源提供實際值；主要逐檔來源不提供，寫入為 0 |
| 資料來源 | 標記欄位 | 記錄實際取得該列資料的來源（交易所快照／主要逐檔來源／備援逐檔來源），用於事後辨認口徑 |

### 同步進度

| Field | Type/Role | Rule |
|---|---|---|
| 作業類型 | 識別鍵之一 | 本功能使用「日線回補」一種類型 |
| 股票代號 | 識別鍵之一 | 每檔股票在同一作業類型下僅一列進度 |
| 狀態 | 進度標記 | 待處理／進行中／完成／失敗／已跳過，依處理結果流轉 |
| 已同步至日期 | 進度標記 | 記錄該檔已處理完成的區間終點，作為斷點續傳與「補到今日」判斷的依據 |
| 嘗試次數 | 重試保護 | 用於避免單一標的無限重試卡住整批作業；來源被封鎖不計入此計數 |

## 限制條件

### 股票主檔
- 新增股票僅能由每日全市場快照（或等同的主檔同步機制）完成；回補類路徑（逐日快照、逐檔查詢）只能寫入既有母體內代號的行情，不得新增主檔股票，也不得將母體外代號寫入主檔。
- 非普通股（ETF、特別股、TDR 等）在停用預設篩選後仍保留於主檔，回補路徑不刪除、不停用任何既有股票，只是預設不再被同步涵蓋。
- 自動主檔同步僅涵蓋上市股票，不涵蓋上櫃。

### 日線價格
- 一律以覆蓋寫入（同檔同日重複處理不會產生重複列），重跑任一日或任一檔為冪等操作。
- 停牌或無交易的日期不得以零值補列，無資料即不寫入。
- 抓法（逐日快照或逐檔查詢）的選擇不影響對外的價格語意：同一區間、同一標的，兩種抓法寫入的開高低收必須相同。
- 單一交易日的行情寫入與其進度推進必須在同一個交易邊界內完成，不得出現「資料已寫入但進度未推進」的中間狀態。

### 同步進度
- 嘗試次數只反映該標的本身的處理失敗，來源被封鎖或暫時查無資料都不得累加。
- 標記「已跳過、不再重試」須所有可用來源皆查無該標的資料才成立，任一來源查無不足以下此結論。
- 回補路徑的「已同步至日期」記錄的是本次請求區間的終點，而非實際寫入的最後一筆資料日期，藉此讓落在非交易日的區間終點也能被正確視為「已處理過」。
- 每日增量推進的則是快照回應中的實際交易日，且只能推進既有進度列、不得為新標的新建進度列，也不得使既有值倒退。
- 續傳參數彼此互斥：「僅處理未完成／失敗標的」與「補到指定日期為止」不可同時使用。

## 跨主題規則

- 全市場回補預設母體為「上市普通股」，其判定規則與其他讀取日線資料的功能（型態掃描、產業別漲幅排行、股票母體匯入）共用同一套代號篩選邏輯，不得存在第二套判定（見 stock-universe-import.md）。
- 本功能是指標運算唯一的資料輸入來源，指標統計功能一律讀取本功能已寫入的資料，不另行對外抓取（見 stock-indicator-statistics.md）。
- 逐檔歷史抓取與分鐘 K 線抓取共用同一套資料解析與正規化邏輯（見 stock-minute-price.md）。
- 嘗試次數上限、進度狀態流轉等同步進度的完整語意由另一份規格定義，本功能只依循該語意寫入與更新（見 ../../specs/dba/stock-sync-progress.md）。
- 系統時區（含資料庫容器與應用程式執行環境）須全系統一致設定為台北時區，相關容器設定與既有資料的一次性時間校正屬於另一主題（見 ../../specs/infra/mysql.md）。
- 前端的同步狀態列顯示依賴本功能進度查詢的既有欄位語意（皆為「檔數」而非「交易日數」）維持不變，才能在不修改前端的情況下正常運作（見 ../../specs/frontend/strategy.md）。

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| POST | /api/stocks/sync/daily | 觸發一次每日例行更新，取得全市場當日行情並同時更新股票主檔與日線價格 | Direct |
| POST | /api/stocks/sync/backfill | 觸發一次歷史行情回補（依是否指定股票代號決定走「指定多檔」或「全市場」模式），並推進各標的的同步進度 | Direct |
| GET | /api/stocks/sync/progress | 查詢指定作業類型目前的同步進度統計（各狀態檔數、失敗清單、最近一次成功完成時間） | Live direct |
