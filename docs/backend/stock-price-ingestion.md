# 股票行情抓取與回補 API

本 API 負責把外部交易所與資料源的日線行情寫入系統，是整個系統唯一的資料入口，並順帶維護股票主檔的代號與名稱。抓取分為三種路徑：每日收盤後的全市場增量更新、指定多檔的歷史回補、以及全市場的歷史回補，其中回補一律以逐檔方式進行並支援斷點續傳。所有寫入一律採用覆蓋式更新，重跑同一標的同一區間為冪等操作，且能修正資料源事後更正的數值；停牌或無交易的日期不會補零，維持「無資料即不寫入」的原則。

## 欄位定義

### 回補請求（POST /api/stocks/sync/backfill）

| Field | Type/Role | Rule |
|---|---|---|
| stockIds | 字串陣列，選填 | 指定要回補的股票代號清單；省略或空陣列代表處理全市場中狀態為「啟用」的全部股票 |
| startDate | 日期，必填 | 回補起日；須早於實際需要的統計起日至少 250 個交易日，作為指標暖身緩衝 |
| endDate | 日期，必填 | 回補迄日；須晚於或等於起日，否則視為錯誤請求 |
| resume | 布林，選填，預設 false | true 時僅接續處理尚未完成或失敗且重試次數未達上限的標的，並從各檔上次完成日期之後接續；false 則重置進度、重新處理全部標的 |

### 進度查詢回應（GET /api/stocks/sync/progress）

| Field | Type/Role | Rule |
|---|---|---|
| jobType | 字串 | 作業類型識別，用於區分不同批次作業（行情回補、指標重建）的進度 |
| total | 整數 | 本次批次涵蓋的標的總數 |
| pending | 整數 | 尚未開始處理的標的數 |
| running | 整數 | 正在處理中的標的數 |
| done | 整數 | 已成功完成的標的數 |
| failed | 整數 | 已達重試上限仍失敗的標的數 |
| skipped | 整數 | 目標區間內查無任何交易資料而略過、不再重試的標的數 |
| failedItems | 物件陣列，最多 50 筆 | 列出部分失敗標的的代號、已嘗試次數與最後錯誤原因，供排查；各狀態數量加總應等於 total |

## 限制條件

- 外部歷史資料來源的免費層不支援一次取得全市場資料，全市場回補必然是逐檔進行的長時間作業
- 逐檔請求需有可設定的速率間隔與並行上限，遇到限流或逾時須採指數退避重試；未經節流的請求會在短時間內被來源封鎖
- 同一作業類型同時僅能有一筆批次作業執行中，重複觸發會被拒絕並說明原因（409）
- 重跑同一標的同一區間為冪等操作，不會造成價格資料重複或錯亂
- 停牌或無交易日不補零，無資料的日期不寫入任何列
- 回補起日需比實際需要的統計起日早至少 250 個交易日，作為暖身緩衝
- 續傳僅處理尚未完成或失敗且未達重試上限的標的，已完成標的不重新發出外部請求
- 區間內查無任何交易資料的標的會被標記為略過，不再重試

## 跨主題規則

- 本模組是全系統唯一的資料入口，指標運算一律以此處寫入的行情資料為輸入，不另行對外抓取行情（見 stock-indicator-statistics.md）
- 回補起日須早於實際需要的統計起日至少 250 個交易日，此暖身緩衝需求源自下游指標運算的收斂要求（見 stock-indicator-statistics.md）
- 停牌日不補零的規範是為避免下游 KD 最低價計算歸零、MACD 產生虛假暴跌訊號（見 stock-indicator-statistics.md）

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| POST | /api/stocks/sync/daily | 以單一請求取得全市場當日收盤行情，同步更新股票主檔並寫入當日價格 | Direct |
| POST | /api/stocks/sync/backfill | 依指定股票清單或全市場觸發歷史行情回補作業 | Async job |
| GET | /api/stocks/sync/progress | 查詢行情回補或指標重建作業的進度 | Direct |
