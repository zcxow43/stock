# 股票行情抓取與回補 API

本 API 負責把外部交易所與資料供應商的股票日線行情寫入系統，並順帶維護股票主檔，是全系統唯一的行情資料入口；所有查詢與統計運算都只讀取本模組寫入的結果，不另外對外抓取。所有寫入動作（每日增量、回補）都是直接套用到正式資料，不經過任何審核流程，屬於即時生效的批次作業；其中「每日增量」在單一請求內同步完成並回應結果，「回補」則是受理後立即回應、實際抓取在背景以逐檔方式進行，並具備斷點續傳能力，可從中斷處接續、可只補齊落後的部分而不重複已完成的工作。系統啟動時會自動觸發一次全市場回補，把所有在市股票的行情補到當天為止，此過程不會延後服務可用時間，也不會因外部來源不可用而讓啟動失敗。

## 欄位定義

**股票主檔（Stock）**

| Field | Type/Role | Rule |
|---|---|---|
| 股票代號 | 識別碼 | 由資料源提供，作為股票的唯一識別 |
| 股票名稱 | 基本資料 | 隨每日增量同步一併更新 |
| 是否在市（is_active） | 狀態旗標 | 決定「全市場」回補與「啟動補齊」的處理範圍；僅在市股票會被自動補齊 |

**股票日線行情（StockDailyPrice）**

| Field | Type/Role | Rule |
|---|---|---|
| 股票代號 | 識別碼（複合唯一鍵之一） | 對應股票主檔 |
| 交易日期 | 識別碼（複合唯一鍵之一） | 採台北日曆日；停牌或無交易的日期不建立該列，不得以 0 補列 |
| 開盤價／最高價／最低價／收盤價 | 數值 | 一律為原始成交價，不做除權息還原；資料源的千分位符號、民國紀年字串須正規化為數值與西元日期 |
| 成交量／成交金額／成交筆數 | 數值 | 隨每日增量或回補寫入 |

**同步進度（StockSyncProgress）**

| Field | Type/Role | Rule |
|---|---|---|
| 作業類型（job_type） | 分類鍵 | 本主題使用 `PRICE_BACKFILL` |
| 股票代號 | 識別碼 | 對應被追蹤的標的 |
| 狀態（status） | 進度狀態 | `PENDING`／`RUNNING`／`DONE`／`FAILED`／`SKIPPED`，流轉語意見進度資料表規格 |
| 最後同步日期（last_synced_date） | 進度標記 | 記錄「已處理完成的請求迄日」，並非最後一筆實際寫入資料的日期 |
| 嘗試次數（attempt_count） | 重試計數 | 因落後而重新開啟時歸零，不沿用先前失敗的次數 |
| 起訖時間戳（started_at／finished_at／updated_at） | 時間戳 | 由資料庫時鐘寫入，時區為 Asia/Taipei |

## 限制條件

**股票主檔**
- `stockIds` 中含主檔不存在的代號時，整批回補請求即被拒絕。

**股票日線行情**
- 停牌或無交易的日期不得補零，也不得建立該日的列。
- 一律以原始成交價寫入，重跑同一檔同一區間必須是冪等操作，且能覆寫資料源事後更正的值。
- 同一檔一次回補的價格寫入與該檔進度更新須在同一交易邊界內完成，避免「資料已寫入但進度未更新」造成重跑時重複向外部要資料。

**同步進度**
- 續傳（`resume=true`）只處理狀態為待處理或失敗、且尚未達重試上限的標的。
- 補齊到指定日（`catchUp=true`）與續傳（`resume=true`）不可同時指定，否則整批請求會被拒絕並回覆錯誤原因。
- 目標區間內查無任何交易資料的標的會標記為「已略過」，不再重試。
- 同一作業類型已有作業執行中時，新的回補請求會被拒絕；系統自動啟動補齊執行期間，手動觸發的回補也視為同一作業類型，同樣會被拒絕。
- 目標標的清單為空（例如尚無任何在市股票）是合法情形，須以零筆目標正常受理並立即結束，不得對外部資料源發出任何請求，也不得造成例外或讓啟動流程失敗。

## 跨主題規則

- 全系統（資料庫容器、應用程式執行環境、資料庫連線）必須統一使用 Asia/Taipei 時區；資料庫時鐘與應用程式時鐘若不一致，會讓「最後同步時間」在畫面上出現固定偏移，也會讓「今日」的判斷在午夜前後產生矛盾。容器端設定與既有資料列的一次性時區校正屬於基礎設施與資料表規格的範圍（見 `specs/infra/mysql.md` 與 `specs/dba/` 下對應的資料表規格）。
- 回補的起日必須早於實際需要的統計起日至少約 250 個交易日，以滿足指標運算的暖身需求（見 `stock-indicator-statistics.md`）。
- 本模組寫入的行情資料是指標統計運算的唯一輸入來源，指標模組不另行對外抓取（見 `stock-indicator-statistics.md`）。
- 進度狀態的完整流轉語意（各狀態的意義與轉換條件）以進度資料表本身的規格為準（見 `specs/dba/stock-sync-progress.md`）。
- 回應中的「已補齊檔數」用來讓呼叫端分辨「這次真的補了資料」與「這次什麼都沒做」，前端的同步呈現必須據此如實顯示，不得將「已補齊」誤呈現為「剛完成同步」（見 `../frontend/strategy.md`）。

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| POST | /api/stocks/sync/daily | 觸發一次全市場當日行情增量同步，並順帶更新股票主檔 | Direct |
| POST | /api/stocks/sync/backfill | 觸發指定標的或全市場的歷史行情回補（含續傳、補齊到指定日等模式） | Direct |
| GET | /api/stocks/sync/progress | 查詢指定作業類型目前的同步進度與最近一次成功完成時間 | Direct |
