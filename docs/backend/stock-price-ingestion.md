# 股票行情抓取與回補 API

本模組是系統唯一的日線行情入口，負責把外部行情寫進系統，並順帶維護股票主檔。所有動作都不需送審，寫入即直接生效；而且一律可重跑，重複執行只會覆蓋、不會產生重複資料。取得行情有三條路：每日收盤後以一次請求取得當日全市場快照；指名少數幾檔時逐檔查歷史；全市場回補時，上市股票改用交易所「逐日全市場快照」（請求數隨天數而非檔數增加），上櫃股票則逐檔查詢。回補以背景方式執行，受理後立即回應（202，非同步受理），進度另以查詢取得，已補到目標日的標的完全不再對外請求，可中斷後續傳。外部來源被封鎖時會自動切換或降級，不把封鎖算成標的本身的失敗；系統啟動時也會自動用同一套回補機制把在市普通股（上市與上櫃）補到今日。

## 欄位定義

**回補請求（POST 回補端點）**

| Field | Type/Role | Rule |
|---|---|---|
| stockIds | 字串清單，選填 | 提供時只處理指名的股票，且不套用普通股篩選；省略或空清單代表全市場。含主檔不存在的代號會被拒絕並列出未知代號（400） |
| commonStocksOnly | 布林，選填 | 預設 true，僅對全市場有效：母體只含普通股（代號恰為 4 位數字且首字非 0）；false 則為全部在市股票。指名模式不生效，回應一律顯示 false |
| startDate | 日期，必填 | 回補起日；須比實際需要的統計起日早至少 250 個交易日（供指標暖身） |
| endDate | 日期，必填 | 回補迄日；早於起日會被拒絕（400） |
| resume | 布林，選填 | 預設 false（重置進度重跑）；true 只處理未完成與失敗、且未達重試上限的標的，從各自已處理日的次日接續 |
| catchUp | 布林，選填 | 預設 false；true 表示補到迄日為止，已補到迄日的標的完全跳過 |

**回補受理回應**

| Field | Type/Role | Rule |
|---|---|---|
| jobType | 作業類型 | 固定為價格回補 |
| targetCount | 目標檔數 | 以「檔」計，不是以天數計；全市場時包含上櫃標的 |
| caughtUpCount | 已補齊檔數 | 受理當下算出已補到迄日、不會發出任何外部請求的檔數；catchUp 為 false 時恆為 0；等於 targetCount 表示這次同步完全沒向外要資料 |
| commonStocksOnly | 實際採用的母體規則 | 照實回報；指名模式恆為 false，用來說明目標檔數為何少於總覽頁的「共 N 檔」 |
| startDate / endDate | 實際區間 | 回報本次區間 |
| mode | 抓取模式 | 指名為 SELECTED，全市場為 ALL |

**每日增量（POST 每日增量端點）**

| Field | Type/Role | Rule |
|---|---|---|
| tradeDate | 日期，選填（請求） | 省略時取資料源當日快照；資料源只能給最新已發布交易日 |
| tradeDate / stockCount / insertedCount / updatedCount（回應） | 統計 | 回報實際交易日、快照檔數與新增／更新的行情筆數 |
| stockMasterUpserted | 主檔檔數（回應） | 等於本次快照涵蓋的主檔檔數，含內容未變而略過寫入者 |

**進度查詢回應**

| Field | Type/Role | Rule |
|---|---|---|
| jobType | 查詢條件 | 指定要查哪一種作業 |
| total | 總檔數 | 等於各狀態檔數之和 |
| pending / running / done / failed / skipped | 各狀態檔數 | 一律以檔計，即使全市場回補實際以逐日方式進行 |
| lastSyncedAt | 最近一次成功完成時間 | 取已完成標的的完成時間最大值；從未成功為空；全部失敗的同步不會更新它 |
| failedItems | 失敗清單 | 最多 50 筆，每筆含股票代號、已嘗試次數、最後錯誤訊息 |

**每檔回補進度（內部紀錄，每檔一列，經由進度查詢呈現）**

| Field | Type/Role | Rule |
|---|---|---|
| 狀態 | 待處理／處理中／已完成／失敗／已跳過 | 封鎖造成的中止不改變狀態；所有來源皆回報查無此標的才標為已跳過 |
| 已處理至日期 | 日期 | 成功處理一個區間後記為該次的迄日，而非最後一筆實際行情日；每日增量則記為快照的實際交易日；只前進、不倒退 |
| 嘗試次數 | 整數 | 只在該檔自身重試耗盡才累加；來源封鎖不累加；catchUp 重新開啟時歸零 |

**日線行情列（寫入內容）**

| Field | Type/Role | Rule |
|---|---|---|
| 交易日 | 台北日曆日 | 民國紀年與千分位字串寫入前須正規化 |
| 開高低收 | 原始成交價 | 未經除權息還原；兩個逐檔來源的價格一致，切換不造成斷層 |
| 成交量 | 股數 | 交易所口徑為全額；Yahoo 系統性偏低（量比中位數約 0.864），切換點會有台階；上櫃標的只有逐檔來源，因此為 Yahoo／FinMind 口徑 |
| 成交金額、成交筆數 | 實際值 | 交易所與 FinMind 提供實際值；Yahoo 不提供，寫入 0 |
| 資料來源 | 標記 | 記錄實際取得該列的來源（交易所／Yahoo／FinMind），用來辨認成交量口徑 |

## 限制條件

- 行情一律使用 UPSERT，重跑冪等，且能修正資料源事後更正的值。
- 價格一律是原始成交價，不使用還原價。
- 停牌或非交易日不補零、不寫列；不得出現價格為 0 的列。
- 沒有交易日曆：全市場回補以日曆天數展開，不預先排除週末假日；非交易日由資料源回空來回答，視為正常處理完畢（不寫列、不記失敗、不累加嘗試次數，且該日進度照常推進）。
- resume 與 catchUp 不可同時為 true（400，無法判讀的組合）。
- 同一作業類型同時只能有一個作業執行（409）；手動回補與啟動補齊共用同一把鎖。
- 起日不得晚於迄日；指名代號必須存在於主檔。
- 標的清單為空是合法情形：以 0 檔正常受理並立即結束，不報錯、不對外請求。
- 全市場預設母體只含上市與上櫃的在市普通股；此參數只縮小抓取範圍，不刪除、不改動任何既有主檔或已寫入行情，母體外代號也不會因逐日快照被寫入或新增主檔。
- 全市場回補依市場別分流：上市標的走逐日快照，上櫃標的（不在交易所快照中）走逐檔查詢，規則與指名模式完全相同；櫃買中心的全市場快照不在本模組範圍內。
- 逐日快照只推進上市標的的進度；上櫃標的不由快照推進，只在其逐檔處理成功後推進。
- 進度只前進不倒退；每日增量只推進既有進度列，不新建進度列（避免總數膨脹成快照檔數），且只推進該次快照涵蓋的代號，推進日期取自回應中的實際交易日而非系統日期。
- 單日（或單檔）的行情寫入與進度推進必須在同一個交易邊界內完成。
- 逐檔來源順位為 Yahoo、FinMind；被封鎖的來源在到期前完全不發出請求，到期後自動切回主來源；封鎖狀態與請求間隔都是全批共用、各來源獨立。
- 封鎖絕不累加嘗試次數；所有來源皆不可用時，不再領取新標的、讓進行中的標的收斂，作業正常結束，剩餘標的維持待處理。
- 單一來源的「查無資料」不足以判定下市：先改用下一個來源，全部來源都查無才標為已跳過。
- 全市場回補時逐日快照被封鎖，降級為逐檔繼續，不結束作業；冷卻到期後下一次作業重新從逐日快照開始。
- 預設同時處理 8 檔，每來源至少間隔 0.5 秒，皆由設定決定；並行只適用逐檔路徑，逐日路徑循序執行。
- 單次進度查詢的失敗清單最多 50 筆。
- 每日增量寫主檔時，內容沒變的股票不寫，只寫新股與有變更者，但行情與進度推進仍涵蓋快照中每一檔。
- 時區一律為 Asia/Taipei；回補起日預設 2026-01-01，已有進度的標的不受影響。
- 備援來源的存取憑證須由部署環境提供，不得進版控；未設定時啟動需留下警告。
- 啟動時的主檔同步與日線補齊各有獨立開關、不得阻塞或使啟動失敗；順序固定為先主檔、後日線；主檔同步只涵蓋上市，日線補齊涵蓋上市與上櫃的在市普通股。

## 跨主題規則

- 全市場回補與啟動補齊所採用的普通股判定（代號恰 4 位數字、首字非 0），與股票清單匯入、型態掃描、產業漲幅排行共用同一份規則，不得有第二套（見 stock-universe-import.md、strategy-scan.md、industry-gain-ranking.md）。
- 本模組不新增股票：「有哪些股票」由主檔與每日增量／啟動主檔同步維護，回補只負責補每檔的日線；每日增量與啟動同步會順帶新增或更新上市股票主檔，上櫃股票需經股票主檔維護手動新增（見 stock-universe-import.md、stock-catalog.md）。
- 進度的狀態流轉、嘗試次數上限與重試語意，由進度表規格定義，本模組只依其規則更新（見 stock-sync-progress.md）。
- 每一次回補作業結束、以及每日增量成功後，三大法人買賣超在背景補齊，本模組的回應、進度與行為不因此改變（見 institutional-trade-ingestion.md）。
- 指標運算、型態掃描與產業漲幅排行都只讀取本模組寫入的行情；成交量口徑差異會影響型態掃描中的量能倍數與法人籌碼佔比，故歷史列需以一次全市場回補統一為交易所口徑（見 stock-indicator-statistics.md、strategy-scan.md、industry-gain-ranking.md）。
- Yahoo 逐檔歷史的解析沿用分 K 的同一套索引配對機制，不另寫一套（見 stock-minute-price.md）。
- 受理回應中的目標檔數、已補齊檔數與母體規則，供前端同步列如實呈現（目標數少於「共 N 檔」的原因、完全沒對外請求時不得顯示成剛完成同步），本模組的欄位語意不得改為天數（見 specs/frontend/strategy.md）。

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| POST | /api/stocks/sync/daily | 取得最新（或指定）交易日的全市場行情，寫入日線並更新主檔，同時推進既有進度，立即生效 | Direct |
| POST | /api/stocks/sync/backfill | 指名多檔或全市場回補一段區間的日線，背景執行，受理後立即回應（202），不需送審 | Direct |
| GET | /api/stocks/sync/progress?jobType=PRICE_BACKFILL | 唯讀查詢回補進度（各狀態檔數、最近成功完成時間、最多 50 筆失敗清單） | Direct |
