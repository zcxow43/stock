# 股票行情抓取與回補 API

本 API 負責把外部行情資料寫入系統，是指標運算與其他讀取日線的功能唯一的資料入口。它提供三種抓取方式——每日全市場快照、指定多檔歷史回補、全市場歷史回補——三者共用同一套速率控制、進度追蹤與寫入邏輯，差別只在標的清單的來源。所有寫入皆為覆蓋式更新，一經受理即直接生效並反映到資料庫，沒有送審流程；其中每日增量在單一請求內完成，回補則是受理後立即回應、實際抓取在背景進行。全市場回補的抓取母體預設只涵蓋上市普通股（排除 ETF、特別股、TDR），可由呼叫端明確覆寫為全部在市股票；若同時指名特定代號則一律照跑，不受此篩選影響。逐檔歷史抓取具備雙來源（Yahoo 為主、FinMind 為備援）自動切換與並行處理（預設同時處理 8 檔、每來源請求間隔 0.5 秒），任一來源被判定封鎖時整批作業會自動改用另一來源或安全暫停，不會把封鎖期內的標的誤判為個別失敗。

## 欄位定義

**每日增量請求**

| Field | Type/Role | Rule |
|---|---|---|
| 交易日 | 目標交易日，選填 | 省略時取資料源當日快照 |

**回補請求**

| Field | Type/Role | Rule |
|---|---|---|
| 指定標的清單 | 標的代號陣列，選填 | 省略或空陣列代表全市場；提供時只處理清單內代號，且不套用普通股篩選（指名優先） |
| 只含普通股 | 全市場母體規則，選填，預設「是」 | 只在未提供指定標的清單時生效；為「是」則母體為代號恰 4 位數字且首字非 0 的上市普通股，為「否」則為全部在市股票 |
| 回補起日 | 區間起點，必填 | 須早於實際需要的統計起日至少 250 個交易日，以滿足指標暖身需求 |
| 回補迄日 | 區間終點，必填 | 須晚於或等於回補起日 |
| 只處理未完成 | 續傳模式，選填，預設「否」 | 依各標的目前狀態（待處理／失敗）判斷是否重新處理；與「補到迄日為止」不可同時成立 |
| 補到迄日為止 | 追平模式，選填，預設「否」 | 依各標的目前已同步到哪一天，決定要不要抓、從哪天接續抓；與「只處理未完成」不可同時成立 |

**回補回應（受理當下）**

| Field | Type/Role | Rule |
|---|---|---|
| 作業類型 | 識別本次批次作業 | 固定為行情回補作業 |
| 目標標的數 | 本次解析出的清單長度 | 依篩選條件解析後的結果，可為 0（合法情形） |
| 已達目標檔數 | 完全不發外部請求的標的數 | 非追平模式時一律為 0；等於目標標的數表示本次未對外部要任何資料 |
| 只含普通股 | 本次實際採用的母體規則 | 指名標的模式下一律為「否」（該模式不套用篩選） |
| 回補起日／迄日 | 本次實際採用的區間 | 原樣回應本次採用的端點 |
| 作業模式 | 指定多檔或全市場 | 依是否提供指定標的清單而定 |

**進度查詢回應**

| Field | Type/Role | Rule |
|---|---|---|
| 作業類型 | 查詢條件回顯 | 對應被查詢的批次作業 |
| 各狀態標的數 | 總數、待處理、處理中、完成、失敗、跳過 | 各狀態加總須等於總數 |
| 最後同步時間 | 最近一次成功完成的時間 | 取自成功完成標的中最新的完成時間；從未成功過為空值，一次全部失敗的同步不會更新此值 |
| 失敗標的明細 | 失敗清單 | 每筆含標的代號、已嘗試次數、最後錯誤原因；最多回傳 50 筆 |

## 限制條件

- **請求驗證**：回補起日晚於迄日、指定標的含系統中不存在的代號、「只處理未完成」與「補到迄日為止」同時成立，皆視為無效請求並拒絕受理（400）；同一作業類型已有一批在執行中時，新的回補請求被拒絕並說明原因（409），須等前一批結束。
- **母體篩選只縮小抓取範圍，不改動任何既有資料**：非普通股在股票主檔中的列不動（是否在市不受影響，總覽頁的檔數因此不變），其已寫入的既有歷史行情也不刪除，只是不再被同步推進；要補某檔非普通股，以指名方式即可。
- **指名優先於預設母體**：一旦提供指定標的清單，普通股篩選完全不生效，即使指名的是 ETF 或特別股也照常處理。
- **目標清單為空是合法情形，不是錯誤**：篩選後一檔都沒有時必須以「目標數 0」正常受理並立即結束，不得拋出例外、不得讓啟動補齊失敗，也不得對外部來源發出任何請求。
- **停牌或無交易的日期一律不補零、不寫入該列**，缺資料就是缺資料，不得以零價格代替。
- **一律採覆蓋式寫入，重跑同一標的同一區間必須是冪等操作**，且能修正資料源事後更正的值。
- **並行抓取下的節流是全批共用，不是每個工作者各自計時**：並行度（預設 8）與每來源請求間隔（預設 0.5 秒）皆由設定決定，且並行不改變追平判斷、同步進度認定、重試次數累加與冪等性等單檔語意。
- **來源被判定封鎖時，不計入該檔的重試次數，也不改變該檔進度狀態**；封鎖判定與速率控制以「來源」為單位，各來源獨立計算、互不影響，且封鎖狀態為整批共用，一經判定其餘工作者即不再對該來源發出請求。
- **單一來源查無此標的不足以判定為永久跳過**，須所有來源皆查無資料才標記為跳過。
- **兩個來源同時無法使用時，本批作業視為正常結束**（非錯誤）：停止領取新標的，已在處理中的標的照常跑完，尚未處理的維持待處理狀態留給下一次接續，不需要額外的補救動作或新增端點。

## 跨主題規則

- 全市場回補的普通股判定（代號恰 4 位數字、首字非 0）與匯入、掃描、漲幅排行必須是同一份共用實作，不得存在第二套代號篩選邏輯（見 stock-universe-import.md、strategy-scan.md、industry-gain-ranking.md）。
- 來源封鎖不計入重試次數，是因為重試上限的用途是「避免單一標的無限重試卡住整批作業」，這個語意由同步進度資料本身定義（見 `specs/dba/stock-sync-progress.md`）。
- 本模組是指標運算（MACD／KD）唯一的資料輸入來源，指標統計不另行對外抓取行情（見 stock-indicator-statistics.md）。
- 回補回應中的母體規則與「已達今日不需重抓」的檔數，是為了讓前端能如實呈現「同步了幾檔、母體是什麼」，避免使用者把它與總覽頁的在市檔數對不起來（見 `specs/frontend/strategy.md`）。
- 股票主檔的「有哪些股票」由清單匯入與每日快照維護，本模組的回補只負責「每檔有哪些日線」，不新增標的（見 stock-universe-import.md）。

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| POST | /api/stocks/sync/daily | 以單一請求取得全市場當日行情，同時更新股票主檔與當日日線 | Direct |
| POST | /api/stocks/sync/backfill | 指定多檔或全市場的歷史行情回補，受理後於背景並行執行 | Direct |
| GET | /api/stocks/sync/progress | 查詢指定作業類型目前的同步進度、最後同步時間與失敗明細 | Live direct |
