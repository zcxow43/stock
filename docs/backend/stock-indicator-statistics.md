# MACD／KD 指標運算與兩個月統計 API

本功能包含兩件事：由日線資料推導 MACD 與 KD 技術指標並存入資料庫，以及提供指定區間（預設兩個月）的行情與指標統計查詢。指標一律由系統自行計算，不採用任何外部服務提供的現成數值，以確保公式一致且可重現。指標運算分為「全量重建」與「每日增量」兩種模式，觸發後立即執行、直接寫入資料庫生效，沒有審核流程；統計查詢則為純讀取，反映資料庫中目前已運算完成的內容，若某檔尚未完成指標運算，仍會誠實回報「尚無指標」而非隱藏或報錯。

## 欄位定義

**每日指標**

| Field | Type/Role | Rule |
|---|---|---|
| stockId / tradeDate | 識別鍵 | 決定唯一一筆指標列 |
| dif / dea / osc | MACD 指標值 | 依 (12,26,9) 參數計算 |
| k / d / j | KD 指標值 | 依台股慣例 (9,3,3)、RMA 平滑計算 |
| isWarmup | 內部標記 | 標示為暖身期間的列，一律不對外呈現 |
| paramKey | 版本標記 | 本階段固定為 MACD_12_26_9__KD_9_3_3 |
| warmupSufficient | 呼叫端可見旗標 | 該檔歷史是否達 250 個交易日暖身門檻；不足時指標仍輸出，但標示尚未收斂 |

**區間統計摘要（查詢時計算，不落地儲存）**

| Field | Type/Role | Rule |
|---|---|---|
| summary 內價格統計（最高、最低、漲跌、成交量等） | 計算值 | 僅需區間內有行情即可計算，不受指標是否運算完成影響 |
| latestDif / latestDea / latestOsc / latestK / latestD / latestJ | 計算值 | 區間內完全無指標列時為空值，代表「尚未運算」 |
| macdGoldenCross / macdDeathCross / kdGoldenCross / kdDeathCross | 交叉次數 | 僅比較相鄰兩個交易日皆有指標值的情形；區間內無指標時為空值（非 0），0 代表「算過但沒發生交叉」 |

## 限制條件

- 指標運算時必須自統計起日往前多取 250 個交易日一併計算作為暖身，暖身區間的結果不對外呈現。
- 歷史不足 250 個交易日的股票仍照常輸出指標，但需明確標示尚未收斂，不得因此隱瞞或拒絕回應。
- 每日增量推進時，若找不到前一交易日的指標列（序列有缺口），不得以預設初始值起算，必須改為標記該檔需要全量重建，避免產生錯誤值污染後續序列。
- 同一時間只允許一筆指標重建作業執行，重複觸發會被拒絕。
- 統計查詢指定股票時上限 50 檔；省略股票代號代表查詢全市場上市中股票，此時一律不提供逐日序列，僅提供摘要，全市場查詢若要求逐日序列會被明確拒絕。
- 查詢一律排除暖身期間的指標列。
- 逐日序列以行情為主、指標為輔：某日有行情但尚未運算指標時，該日仍會出現在序列中且價格與成交量完整，僅指標欄位為空值。
- 指標公式與參數為固定契約，即便與外部圖表平台數值不同也不得為求一致而更動。

## 跨主題規則

- 指標運算所需的日線 OHLC 資料，來自每日排程抓取維護的行情資料（見 stock-price-ingestion.md）。
- 全市場範圍以股票主檔中「上市中」的股票為準，該主檔由每日排程抓取維護（見 stock-price-ingestion.md）。
- 指標重建作業的執行進度查詢，共用既有回補作業的進度查詢介面（見 stock-price-ingestion.md）。

## API 清單
| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| POST | /api/stocks/indicators/rebuild | 觸發指定股票或全市場的 MACD／KD 指標重新運算（全量或每日增量） | Direct（觸發後立即執行並直接寫入，無需送審） |
| GET | /api/stocks/statistics | 查詢指定股票或全市場的區間行情與指標統計 | Live direct |
