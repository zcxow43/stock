# MACD／KD 指標運算與兩個月統計 API

本 API 負責讀取行情資料自行推導 MACD 與 KD 兩項技術指標並落地保存，不從任何外部服務取得指標數值，同時提供區間（預設兩個月）行情與指標的統計查詢，可查指定多檔或全市場。指標重算與統計查詢兩者皆直接生效，沒有審核流程；重算可以是全量重建整條序列，也可以是每日增量推進，兩者對外呈現一致的查詢結果。運算需要往前多取一段歷史暖身讓遞迴指標收斂，暖身區間的結果會落地保存但不對外呈現。系統在啟動完成、把行情補齊到今日之後，會自動在背景以增量模式對全市場觸發一次指標重算，不需要任何人手動呼叫，重算失敗也不會影響應用程式啟動。

## 欄位定義

**股票每日技術指標**

| Field | Type/Role | Rule |
|---|---|---|
| 交易日期 | 序列鍵 | 與行情表為外連接關係，某日有行情但尚未算出指標時仍出現在序列中 |
| MACD 相關值（DIF／DEA／柱狀值） | 數值 | 依固定參數（12,26,9）推導，回應以 4 位小數呈現，中間計算不四捨五入 |
| KD 相關值（K／D／J） | 數值 | 採台股慣例參數（9,3,3）與 RMA 平滑，J 值恆等於 3×K − 2×D |
| 遞迴中間狀態 | 內部延續值 | 供每日增量推進使用；找不到前一交易日狀態時不得以初始值起算，須標記該檔需全量重建 |
| 暖身旗標 | 是／否 | 統計起日往前 250 個交易日的推導結果標記為暖身，不對外呈現 |
| 參數版本鍵 | 識別碼 | 目前固定為單一組合，用以標示本批指標對應哪一組公式參數 |

## 限制條件

**股票每日技術指標**
- 暖身區間（統計起日往前 250 個交易日）之指標列會寫入但標記為暖身、不對外呈現。
- 若某檔可用歷史不足 250 個交易日，仍照常運算並輸出，但需標示暖身是否充足，不得因暖身不足而隱瞞或拒絕回應。
- 增量推進時若找不到前一交易日的指標列（序列有缺口），不得以初始值起算，須將該檔標記為需要全量重建。
- 指標公式與參數（MACD 12,26,9；KD 台股慣例 9,3,3、RMA 平滑）為固定契約，不得為了與其他平台的數值一致而更動。
- 同一種指標重算作業同時只能有一筆執行中，重複觸發會被拒絕並說明原因（409）。

**統計查詢**
- 指定標的查詢上限 50 檔，超過即拒絕。
- 全市場查詢一律不含逐日序列，僅回摘要；即使請求要求包含序列也需明確拒絕而非默默截斷。
- 交叉次數判定僅比較「相鄰交易日皆有指標值」的情況，任一日缺指標時不計入該組，也不中斷後續比較。
- 摘要中的最新指標值與四個交叉次數欄位，在區間內完全無指標時為「尚未算過」（null），需與「算過但沒發生」（0）明確區分。

## 跨主題規則
- 指標運算完全以行情模組寫入的日線 OHLC 為輸入，不另行對外抓取指標數值（見 stock-price-ingestion.md）。
- 逐日序列以行情表為主表、指標表為外連接，因為行情已補齊但指標尚未重算是正常的中間狀態，此狀態的存在正是由於兩個模組各自獨立寫入所致（見 stock-price-ingestion.md）。
- 系統啟動完成、行情批次補齊到今日之後，會自動以增量模式對全市場觸發一次指標重算；此為**啟動觸發**而非任何 HTTP 端點觸發，沒有對應請求／回應，觸發時機在行情批次完全結束之後、不與其並行（見 stock-price-ingestion.md）。
- 指標重算與行情批次共用同一組啟動補齊設定開關，關閉時兩者皆不自動觸發；但兩者執行中各自使用不同的作業種類鍵，彼此的併發鎖互不影響（見 stock-price-ingestion.md）。
- 指標的公式與參數定義以指標資料表本身的定義為唯一契約，本模組僅負責依契約運算與落地（見 stock-daily-indicator.md）。

## API 清單
| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| POST | /api/stocks/indicators/rebuild | 對指定標的或全市場觸發指標運算（全量重建或每日增量） | Direct |
| GET | /api/stocks/statistics | 查詢指定區間內的行情與指標統計（逐日序列與區間摘要） | Direct（查詢） |
