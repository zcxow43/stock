# 策略型態掃描 API API

本功能讓使用者對台股掃描是否出現特定價格型態、法人籌碼型態或技術指標交叉，一次最多可勾選十種型態並各自帶入不同判定條件，回報哪些股票在指定區間內命中、命中日與可進場的日期。所有判定都是**查詢當下即時運算**，不會把命中結果或任何中間指標值寫回資料庫，因此同一批行情、同一組參數，任何時候重算都會得到一致答案；也因為不落地任何資料，本功能沒有「送審」或「生效延遲」的概念——呼叫即得到當下最新結果。本功能只回報型態偵測與訊號，不提供、也不得暗示為買賣建議。

## 欄位定義

**策略目錄項目**（`GET /api/strategies` 回應每一筆）

| Field | Type/Role | Rule |
|---|---|---|
| `code` | 策略代號 | 十個固定值之一；前端與後端皆以此識別策略，不得新增未列於本規格的代號 |
| `name` | 策略顯示名稱 | 業務語言（如「箱型突破」） |
| `description` | 策略說明文字 | 無靈敏度型態才在策略層級提供；有靈敏度型態的說明改放在各 `presets` 項目裡 |
| `presets` | 靈敏度清單 | 有靈敏度的三型態（箱型突破、底底高、上漲支撐）固定回三段（`STRICT`/`STANDARD`/`LOOSE`）；其餘七型態固定為空陣列 |
| `params` | 可輸入參數清單 | 只有無靈敏度型態才列出；每項描述一個輸入欄位（名稱、單位、預設、範圍、步進）。單位可為空字串（無單位），下限可為負數 |
| `params[].lessThan` | 參數間的大小限制 | 值為同一策略另一個參數的代號，表示本參數必須嚴格小於該參數；目前只有 MACD 黃金交叉的短期 EMA 使用 |
| `paramGroups` | 可整組開關的選用參數群組 | 目前只有反彈的 `rise` 群組使用；未歸屬任何群組的參數恆生效、不可關閉 |

**掃描參數**（`POST /api/strategies/scan` 中 `strategies[]` 每一筆，依 `code` 決定哪些欄位適用）

| Field | Type/Role | Rule |
|---|---|---|
| `code` | 策略代號 | 同一次請求中不得重複出現 |
| `preset` | 靈敏度 | 僅箱型突破／底底高／上漲支撐三型態必填；其餘七型態不得帶 |
| `risePercent` | 幅度門檻（依型態意義不同） | 僅五個型態接受：三個有靈敏度型態用來覆寫該靈敏度的漲幅欄位（上限 20%）、累積上漲與反彈為窗口/反彈累積漲幅（上限 50%）；三個法人籌碼型態與兩個技術指標型態一律不接受 |
| `days` | 累積上漲回看天數 | 僅累積上漲接受，`1`～`90`，預設 `20` |
| `requireRise`／`dropDays`／`dropPercent`／`riseDays` | 反彈專屬參數 | 僅反彈接受；`requireRise` 關閉時 `riseDays`／`risePercent` 不得帶 |
| `investors` | 法人複選 | 僅三個法人籌碼型態接受；`FOREIGN`／`TRUST` 至少一個、不得重複，省略時兩者皆選 |
| `windowDays` | 法人窗口交易日數 | 僅法人買賣超佔比、法人買超強度排名接受，`1`～`20`，預設 `5` |
| `ratioPercent` | 佔比門檻 | 僅法人買賣超佔比接受，`0`～`100`，最多一位小數，預設 `10` |
| `buyDays` | 連續買超天數 | 僅法人連續買超接受，`1`～`20`，預設 `5` |
| `topN` | 每日取前幾名 | 僅法人買超強度排名接受，`1`～`50`，預設 `10` |
| `fastPeriod` | MACD 短期 EMA 天數 | 僅 MACD 黃金交叉接受，`2`～`50`，預設 `12`，須嚴格小於 `slowPeriod` |
| `slowPeriod` | MACD 長期 EMA 天數 | 僅 MACD 黃金交叉接受，`3`～`100`，預設 `26` |
| `jThreshold` | KDJ 交叉前一日 J 上限（不含） | 僅 KDJ 黃金交叉接受，`-100`～`100`，最多一位小數，預設 `40` |
| `stockIds`／`commonStocksOnly`／`startDate`／`endDate` | 掃描範圍與區間（請求層級，非逐策略） | `stockIds` 上限 200 檔；`commonStocksOnly` 省略視為 `true`；`stockIds` 有值時不套用 `commonStocksOnly` |

**命中結果項目**（每策略 `results[]` 之下的 `items[]`）

| Field | Type/Role | Rule |
|---|---|---|
| `stockId`／`stockName` | 命中股票 | — |
| `signalDate` | 訊號日 | 型態成立所依據的交易日；同一檔在區間內多次命中只回報最近一次 |
| `buyDate` | 進場日 | 五個價格型態中四個（箱型突破、底底高、反彈、累積上漲）與兩個技術指標型態等於 `signalDate`；上漲支撐為 D+2；三個法人籌碼型態為 D 之後下一個交易日 |
| `detail` | 型態專屬判定數值 | 形狀依策略不同（MACD 為交叉當日的 DIF／DEA／OSC 與前一日 OSC；KDJ 為當日與前一日的 K／D／J，皆四位小數），供使用者對照判定依據，不參與任何進一步運算 |
| `insufficientData` | 前置資料不足清單（策略層級） | 與 `items` 互斥，不視為未命中 |
| `pendingConfirm` | 待確認清單（策略層級） | 僅箱型突破（`confirmBars=2`）、上漲支撐、三個法人籌碼型態可能非空；反彈、累積上漲、兩個技術指標型態恆為空陣列 |
| `dataThroughDate` | 法人資料涵蓋至哪一天（僅三個法人籌碼型態） | 說明法人資料的新鮮度，與命中與否無關 |

## 限制條件

**策略目錄與掃描參數**
- `code` 為十個固定值之一，不得混用不存在的策略代號或靈敏度代號
- 有靈敏度型態（箱型突破、底底高、上漲支撐）必填 `preset`；無靈敏度型態不得帶 `preset`
- 靈敏度只改門檻數值，不改判定邏輯；`risePercent` 覆寫也只改對應那一欄門檻，不影響靈敏度決定的其餘參數
- `risePercent` 上限依型態分兩級：箱型突破／底底高／上漲支撐為 `0`～`20`，反彈／累積上漲為 `0`～`50`；三個法人籌碼型態與兩個技術指標型態一律不接受 `risePercent`
- `fastPeriod` 必須嚴格小於 `slowPeriod`（其一省略以預設值比較），否則視為「永遠不可能命中」而拒絕受理；兩欄各自超出範圍時先回該欄的範圍錯誤
- `jThreshold` 允許負值（`-100`～`100`），因為 J 值本身無上下界；判定為嚴格小於
- 一個永遠不可能命中的請求（參數矛盾或超出型態合理範圍）一律在受理前拒絕，不受理後回零命中
- 同一次請求中同一策略 `code` 不得重複
- `stockIds` 上限 200 檔，超過即拒絕而非截斷；清單內允許已下市股票與非普通股，且此時 `commonStocksOnly` 不生效

**技術指標型態（MACD 黃金交叉、KDJ 黃金交叉）**
- 指標自區間起日之前最多 250 個交易日起即時運算；訊號日之前不足 100 個交易日的日子不判定，整段區間都無法判定的股票列入資料不足
- KD 參數固定為 (9,3,3)、MACD 訊號線固定為 9 日，只有 MACD 的短期／長期 EMA 天數可調
- KDJ 的「J 向上突破 K 與 D」必然與 K 突破 D 同一天發生，判定以 K 與 D 比較，不以 J 的數值直接比較

**命中結果**
- `insufficientData` 與 `matchedCount`／`items` 互斥：同一檔不會同時出現在兩處
- `pendingConfirm` 中的股票不計入 `matchedCount`，且僅限箱型突破（`confirmBars=2`）、上漲支撐、三個法人籌碼型態三類情境會產生
- `items` 依 `signalDate` 新到舊排序，同日依 `stockId` 升冪；每檔在區間內只回報最近一次命中
- 本模組不落地任何結果表或中間指標值，技術指標資料表不因本功能新增欄位或被寫入

## 跨主題規則

- MACD 與 KD 的公式、初始值與輸出精度須與指標運算共用同一套實作，兩者以相同輸入算出的值必須一致，不得另行實作一份公式（見 stock-indicator-statistics.md）。
- 黃金交叉（MACD 與 KDJ）的定義沿用既有的交叉判定表，以相鄰兩個交易日比較，不得自訂另一套交叉邏輯（見 stock-indicator-statistics.md）。
- MACD／KDJ 兩個技術指標型態即時運算指標值，不讀取也不寫入指標資料表——該表只存一組固定參數，涵蓋範圍又取決於指標重建何時執行，用它判定會讓掃描結果隨無關排程改變（見 stock-indicator-statistics.md）。
- 技術指標型態的暖身門檻取 100 個交易日而非 250，是因為行情自 2026-01-01 起才開始累積，要求 250 根會讓每一檔都無法判定（見 stock-price-ingestion.md）。
- 三個法人籌碼型態讀取的外資／投信買賣超股數，其抓取與寫入時機、以及「當日尚未抓取」的判斷依據，由另一個模組負責產出（見 institutional-trade-ingestion.md）。
- 法人籌碼型態判定所用的成交股數分母，其歷史來源若非目前主要來源，量能會系統性偏低，導致佔比與強度被高估；本功能不自行修正，修正由上游一次性補正完成（見 stock-price-ingestion.md）。
- `commonStocksOnly` 篩選普通股的代號規則，與股票母體匯入時「只收普通股」的定義共用同一套判斷，不得各自實作（見 stock-universe-import.md）。
- `stockIds` 中代號是否存在，依股票主檔判斷，不存在者直接拒絕整次請求（見 stock-catalog.md）。
- 每一筆命中回報的 `buyDate`，是回測模組據以用收盤價計算報酬的進場依據；「型態何時確認成立」這件事由本功能認定並回報，回測不得自行重新推算（見 strategy-backtest.md）。

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| GET | `/api/strategies` | 取得目前可用的十種策略型態、其靈敏度或可輸入參數規格，供前端動態產生掃描設定介面 | Live direct |
| POST | `/api/strategies/scan` | 依勾選的策略與參數，對指定股票母體與區間即時掃描並回報命中清單、待確認清單與資料不足清單 | Live direct |
