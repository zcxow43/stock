# 策略型態掃描 API

此 API 用來對股票的日線行情（部分型態另外讀取三大法人買賣超與技術指標）做型態偵測，回報哪些股票在指定期間內出現使用者勾選的型態，例如箱型突破、底底高、法人買超強度排名、MACD 黃金交叉等。所有判定都在查詢當下即時運算完成，不會把命中結果或任何中介計算值存起來——判定完全由呼叫端傳入的參數決定，同一批行情換一組參數就是另一組答案，把結果存起來反而會產生「這筆是用哪組參數算的」這種問題。這是一個純查詢功能，沒有新增、修改或刪除任何資料的動作，也沒有送審流程：呼叫端送出掃描條件，系統直接算出並回傳當下的命中清單，不存在「已送出但尚未生效」的中間狀態。若請求在規則上永遠不可能有任何命中（例如參數超出型態合理範圍、或造成邏輯上不會發生交叉的組合），系統會直接拒絕並說明原因（400），而不是受理後回傳零筆結果，以免使用者把「參數填錯」誤認為「掃描結果」。

## 欄位定義

**掃描請求（共通條件）**

| Field | Type/Role | Rule |
|---|---|---|
| strategies | 陣列，必填 | 至少勾選一個型態；同一型態代碼不可重複出現 |
| stockIds | 字串陣列，選填 | 省略或空陣列代表以全市場在市股票為掃描母體；有指定時只掃描清單內股票，允許包含已下市股票與非普通股，不受普通股篩選限制；上限 200 檔，超過即拒絕，不會被默默截斷 |
| commonStocksOnly | 布林，選填 | 省略時視為是；是否只保留代號恰為四位數字且首字元非 0 的普通股（排除 ETF／特別股／TDR）；`stockIds` 有值時本欄位不生效；只影響本次掃描母體，不異動任何主檔資料 |
| startDate | 日期，選填 | 省略時為 `endDate` 往前一個日曆月；不可晚於 `endDate` |
| endDate | 日期，選填 | 省略時為今日 |

**型態參數 — 有靈敏度型態（箱型突破／底底高／上漲支撐）**

| Field | Type/Role | Rule |
|---|---|---|
| preset | 字串，這三型態必填 | 嚴格／標準／寬鬆三選一，決定回看長度、擺動根數、量能倍數、確認根數、盤整前提等其餘參數 |
| risePercent | 數值，選填 | 覆寫該型態靈敏度表中的漲幅門檻；省略沿用靈敏度預設值；範圍 0~20，最多一位小數；填 0 代表不驗證漲幅，不是關閉型態 |

**型態參數 — 累積上漲**

| Field | Type/Role | Rule |
|---|---|---|
| days | 整數，選填 | 回看窗口交易日數，1~90，預設 20 |
| risePercent | 數值，選填 | 窗口內累積漲幅門檻，0~50、最多一位小數，預設 15 |

**型態參數 — 反彈**

| Field | Type/Role | Rule |
|---|---|---|
| requireRise | 布林，選填 | 是否另外套用反彈幅度條件；預設是；關閉時只以跌幅判定 |
| dropDays | 整數，選填 | 跌段回看交易日數（含谷底當日），1~90，預設 3 |
| dropPercent | 數值，選填 | 自窗口最高收盤起算的跌幅門檻，0~50、最多一位小數，預設 10 |
| riseDays | 整數，選填 | 僅 `requireRise` 為是時可帶；谷底之後容許反彈達標的交易日數，1~90，預設 1 |
| risePercent | 數值，選填 | 僅 `requireRise` 為是時可帶；自谷底收盤起算的反彈幅度門檻，0~50、最多一位小數，預設 5 |

**型態參數 — 法人籌碼型態（法人買賣超佔比／法人連續買超／法人買超強度排名共用）**

| Field | Type/Role | Rule |
|---|---|---|
| investors | 字串陣列，選填 | 外資（不含外資自營商）與投信其中之一或兩者，至少一個、不可重複；省略時為兩者皆選；勾選的每一方各自獨立判定，任一方達標即命中 |
| windowDays（法人買賣超佔比／法人買超強度排名） | 整數，選填 | 窗口交易日數（含訊號日），1~20，預設 5 |
| ratioPercent（僅法人買賣超佔比） | 數值，選填 | 買賣超佔成交量比例門檻，0~100、最多一位小數，預設 10 |
| buyDays（僅法人連續買超） | 整數，選填 | 連續買超交易日數（含訊號日），1~20，預設 5 |
| topN（僅法人買超強度排名） | 整數，選填 | 每一方每個交易日取的名次數，1~50，預設 10 |

**型態參數 — 技術指標型態**

| Field | Type/Role | Rule |
|---|---|---|
| fastPeriod（僅 MACD 黃金交叉） | 整數，選填 | 短期 EMA 天數，2~50，預設 **5**；必須嚴格小於 `slowPeriod` |
| slowPeriod（僅 MACD 黃金交叉） | 整數，選填 | 長期 EMA 天數，3~100，預設 **20**；訊號線天數固定為 9，不開放指定 |
| jThreshold（僅 KDJ 黃金交叉） | 數值，選填 | 交叉前一交易日 J 值的上限（不含），-100~100、最多一位小數，預設 40；KD 固定 (9,3,3)，不開放指定 |

**命中結果（每筆型態回應中的命中項目）**

| Field | Type/Role | Rule |
|---|---|---|
| stockId／stockName | 字串 | 命中股票代號與名稱 |
| signalDate | 日期 | 該檔在區間內最近一次命中的訊號日；同一檔多次命中只回報最近一次 |
| buyDate | 日期 | 這次命中對應的進場日，即型態確認成立、可用其收盤價買進而不含未來資訊的交易日；上漲支撐為訊號日之後第 2 個交易日，法人籌碼型態為訊號日之後下一個交易日，其餘型態等於訊號日 |
| detail | 物件，依型態而異 | 回報該次命中的判定數值（如箱高、突破幅度、5 日均線低點序列、DIF/DEA、K/D/J 等）供對照判定依據，不作為操作建議 |

**命中結果（策略層級回應欄位）**

| Field | Type/Role | Rule |
|---|---|---|
| matchedCount | 整數 | 該策略本次的命中檔數 |
| insufficientData | 字串陣列 | 前置資料不足以完成判定的股票，不視為未命中，不計入命中數 |
| pendingConfirm | 字串陣列 | 已達成部分條件但確認資料尚未到齊的股票（箱型突破確認根數未到、上漲支撐 D+1/D+2 未到、法人籌碼型態尚無下一個交易日），不計入命中數 |
| dataThroughDate（僅法人籌碼型態） | 日期或空 | 說明法人買賣超資料實際涵蓋到哪一天，區分「近期沒有命中」與「近期法人資料還沒發布」 |

## 限制條件

- 掃描母體上限 200 檔，超過即拒絕，不會被默默截斷。
- `risePercent` 上限依型態認定：箱型突破／底底高／上漲支撐為 0~20；反彈／累積上漲為 0~50；三個法人籌碼型態與兩個技術指標型態一律不接受 `risePercent`。
- 有靈敏度的三型態（箱型突破、底底高、上漲支撐）必須指定靈敏度；無靈敏度型態（累積上漲、反彈、三個法人籌碼型態、兩個技術指標型態）不得帶靈敏度。
- 漲幅覆寫只改門檻數值、不改判定邏輯；填 0 等同「不驗證漲幅」，不是關閉整個型態。
- 底底高的平滑天數固定為 5 日，不隨靈敏度改變、也不開放呼叫端指定。
- 上漲支撐的確認天數固定為 2 個交易日，不受靈敏度或呼叫端覆寫。
- MACD 黃金交叉的短期 EMA 天數必須嚴格小於長期 EMA 天數，兩者相等或反轉都會讓黃金交叉永遠不會發生，這類請求會被拒絕；訊號線天數固定為 9，不開放指定。
- KDJ 黃金交叉的 KD 參數固定為 (9,3,3)，不開放呼叫端調整。
- 每個型態的專屬參數只能用於該型態本身，帶入不適用的型態即拒絕整個請求。
- 同一次掃描不可重複勾選同一型態代碼。
- 一個在規則上永遠不可能命中的請求要被拒絕，不能受理後回傳零筆結果。
- 所有結果全部即時運算、不落地任何資料表；同一請求換一組參數就是另一組結果，沒有「歷史掃描紀錄」可回查。
- `insufficientData`（前置資料不足）與命中結果互斥，不算未命中；已命中但確認資料未到齊的另外歸類為 `pendingConfirm`，同樣不計入命中數。

## 跨主題規則

- 普通股篩選（僅留代號恰為四位數字且首字元非 0 的股票，藉此排除 ETF／特別股／TDR）沿用同一套判斷，不得各自實作第二份定義（見 `stock-universe-import.md`）。
- 法人籌碼型態讀取的外資、投信買賣超股數與成交股數，取自三大法人買賣超資料，該資料由日報流程寫入；資料尚未抓取的交易日會讓該檔在該日不判定（見 `institutional-trade-ingestion.md`）。
- 法人籌碼型態的成交量分母來源若落在歷史 Yahoo 寫入的列上會系統性偏低，導致佔比與強度被高估，此偏差的成因與修正方式記載在資料寫入規則中，本掃描不另做修正（見 `stock-price-ingestion.md`）。
- MACD 與 KD 的公式、初始值與精度必須與既有指標運算共用同一套實作，兩個技術指標型態不得另寫一份，以免同一段行情算出不同的交叉日（見 `stock-indicator-statistics.md`）。
- 黃金交叉（含 KD 黃金交叉的等價定義）沿用既有交叉判定的定義，一律以相鄰交易日比較，不因停牌造成的日曆間隔做插補（見 `stock-indicator-statistics.md`）。
- 每一筆命中回報的進場日，是回測依收盤價買進所使用的日期，型態何時確認成立由本掃描定義並回報，不得由呼叫端或回測端自行推算（見 `strategy-backtest.md`）。
- `stockIds` 指定的代號須存在於股票主檔中，否則整個請求被拒絕（見 `stock-catalog.md`）。

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| GET | /api/strategies | 查詢目前支援哪些型態、其靈敏度說明與可調參數的預設值與範圍 | Live direct |
| POST | /api/strategies/scan | 依勾選的型態與參數，對股票母體即時掃描並回傳命中清單 | Live direct |
