# 策略型態掃描 API

此 API 在既有的股票日線行情上做型態偵測，回報哪些股票在指定期間內出現了特定價格型態，目前支援底底高、箱型突破、上漲支撐、反彈、累積上漲五種型態，每種型態各提供嚴格／標準／寬鬆三段靈敏度，且幅度門檻可由呼叫端自行輸入覆寫。模組只讀取行情、即時運算並回傳結果，不落地儲存任何命中資料——型態判定完全隨參數而變，把結果存起來反而會產生「這筆是用哪組參數算的」這類追蹤問題，而重新計算的成本本來就低。掃描母體預設只涵蓋上市普通股（排除 ETF、特別股、TDR），區間預設為近一個日曆月，兩者皆可覆寫。所有回應欄位與文案一律以「命中／訊號／型態」表述，不得使用「建議買進」「推薦」「進場」「出場」等暗示操作方向的措辭——這是本模組刻意設定的契約立場，用來區分「型態偵測」與「操作建議」。

## 欄位定義

**掃描請求（`POST /api/strategies/scan`）**

| Field | Type/Role | Rule |
|---|---|---|
| `strategies` | 陣列，必填 | 至少一個；同一策略代碼不得重複出現 |
| `strategies[].code` | 策略代碼，必填 | 箱型突破／底底高／上漲支撐／反彈／累積上漲五者之一 |
| `strategies[].preset` | 靈敏度代碼，必填 | 嚴格／標準／寬鬆三者之一，決定該策略除漲幅門檻外的其餘判定參數 |
| `strategies[].risePercent` | 覆寫值，選填 | 覆寫該策略的漲幅門檻，取代靈敏度預設值；範圍 0～20，最多一位小數；省略則沿用靈敏度預設值；`0` 代表「不驗證漲幅」，不是關閉該型態。三個策略各覆寫不同參數：箱型突破覆寫突破幅度、底底高覆寫每段遞增的最小漲幅、上漲支撐覆寫單日漲幅門檻，其餘參數一律不受影響 |
| `stockIds` | 股票代號清單，選填 | 省略或空陣列＝掃描全部在市股票；有值時只掃清單內股票且允許包含已下市股票與非普通股；上限 200 檔，超過即拒絕 |
| `commonStocksOnly` | 母體篩選開關，選填 | 省略時視為 `true`；只掃代號恰為 4 位數字且首字元非 `0` 的普通股；`stockIds` 有值時本欄位不生效；只影響掃描母體，不寫入任何資料表 |
| `startDate` | 區間起日，選填 | 省略時為 `endDate` 往前一個日曆月 |
| `endDate` | 區間迄日，選填 | 省略時為今日 |

**掃描結果項（單一策略的命中清單）**

| Field | Type/Role | Rule |
|---|---|---|
| `strategy` / `preset` | 回報用標示 | 對應請求送入的策略代碼與靈敏度 |
| `matchedCount` / `items` | 命中清單 | `items` 依命中日由新到舊排序，同日依股票代號升冪；同一檔在區間內多次命中只回報最近一次 |
| `items[].signalDate` | 命中日期 | 箱型突破為突破日；底底高為最後一段遞增完成日；上漲支撐為上漲日本身，而非確認完成日 |
| `insufficientData` | 前置資料不足清單 | 與 `matchedCount` 互斥，代表「資料不夠所以沒掃」，不是「掃過沒型態」 |
| `pendingConfirm` | 待確認清單 | 已符合初步條件但確認資料尚未到齊（箱型突破的次日確認、上漲支撐的 D+1／D+2 確認）；不計入 `matchedCount` |

**反彈判定明細（`detail`，於 `REBOUND`）**

| Field | Type/Role | Rule |
|---|---|---|
| peakDate／peakClose | 回看窗口高點 | 窗口內最高收盤的日期與價格 |
| troughClose | 訊號日收盤 | 高點之後至訊號日為止的最低收盤 |
| dropPercent | 跌幅 | (高點收盤 − 訊號日收盤) ÷ 高點收盤，即被請求的 `risePercent` 覆寫的門檻 |

**累積上漲判定明細（`detail`，於 `CUMULATIVE_RISE`）**

| Field | Type/Role | Rule |
|---|---|---|
| troughDate／troughClose | 回看窗口低點 | 窗口內最低收盤的日期與價格 |
| peakClose | 訊號日收盤 | 低點之後至訊號日為止的最高收盤 |
| risePercent | 漲幅 | (訊號日收盤 − 低點收盤) ÷ 低點收盤，即被請求的 `risePercent` 覆寫的門檻 |

## 限制條件

- 靈敏度只改判定的其餘參數（回看長度、擺動根數、量能倍數、確認根數、盤整前提），不改判定邏輯本身。
- 每個策略的 `risePercent` 覆寫只作用於該策略參數表中指定的單一欄位，不影響同一策略的其他參數。
- `risePercent` 為 `0` 時等同「不驗證漲幅」，不是關閉整個型態。
- `risePercent` 超出 0～50 或小數超過一位即拒絕（400），並指出是哪一個策略的值不合法。
- `stockIds` 有值時，`commonStocksOnly` 一律不生效——使用者明確指名的股票不受母體過濾。
- `stockIds` 上限 200 檔，超過即拒絕而非默默截斷。
- 上漲支撐的確認長度固定為 2 個交易日，不隨靈敏度改變、也不受 `risePercent` 覆寫影響。
- 上漲支撐不驗證成交量，僅看價格。
- 型態判定一律以相鄰交易日比較，遇停牌造成的日曆間隔不做插補。
- 前置資料不足的股票列入 `insufficientData`，不視為未命中；兩者必須分開回報。
- 全市場掃描的行情讀取須批次進行，不得逐檔查詢。
- 回應欄位名與說明文字不得出現「建議買進」「推薦」等暗示操作的措辭。

## 跨主題規則

- `commonStocksOnly` 篩選採用的「只收普通股」定義（代號恰為 4 位數字、首字元非 `0`）並非本 spec 新訂，而是沿用並共用同一份判斷實作，不得各自為政（見 [stock-universe-import.md](stock-universe-import.md)）。
- 型態判定所需的日線行情來自既有行情資料，本模組僅讀取、不新增或修改任何行情（見 [stock-price-ingestion.md](stock-price-ingestion.md)）。
- 掃描範圍中「全部股票」的認定依股票主檔的在市狀態決定（見 [stock-catalog.md](stock-catalog.md)）。
- 型態判定「以相鄰交易日比較、不因停牌造成的日曆間隔插補」的規則，與技術指標的交叉判定一致，不得各自為政（見 [stock-indicator-statistics.md](stock-indicator-statistics.md)）。

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| GET | /api/strategies | 取得可用策略清單與各策略三段靈敏度的說明文字 | Live direct |
| POST | /api/strategies/scan | 依指定策略、靈敏度與可選的漲幅門檻覆寫，對股票母體做型態偵測並即時回傳命中清單 | Live direct |
