# 策略型態掃描 API

策略型態掃描 API 在既有的日線行情上做型態偵測，回報哪些股票在指定區間內出現了「底底高」「箱型突破」「上漲支撐」「反彈」「累積上漲」五種型態之一。呼叫端指定要掃的型態、各型態的靈敏度或自訂參數，以及要掃的股票範圍與區間，系統即時計算並回報命中清單；這個模組只讀取行情、不落地任何結果，因為型態判定完全由參數決定，換一組參數就是另一組答案，重算的成本本來就低。每一筆命中除了型態成立的訊號日之外，另外回報一個「進場日」，代表這個型態確認成立、可以據以買進的那一天——多數型態進場日等於訊號日，只有上漲支撐因為需要兩天確認而把進場日往後推。本模組回報的一律是型態偵測結果，不是操作建議。

## 欄位定義

### 掃描請求（`strategies[]`，每筆為一個型態設定）

| Field | Type/Role | Rule |
|---|---|---|
| `code` | 型態代碼 | 必填；限定為五個型態之一；同一次請求不得重複出現同一代碼 |
| `preset` | 靈敏度 | 僅箱型突破／底底高／上漲支撐可帶且必填（`STRICT`/`STANDARD`/`LOOSE`）；累積上漲與反彈不得帶 |
| `risePercent` | 幅度門檻覆寫 | 對有靈敏度的三個型態是覆寫該型態的漲幅欄位，省略沿用靈敏度值；對累積上漲是窗口累積漲幅門檻，省略為 15；對反彈是反彈幅度門檻，省略為 5；上限依型態分兩級：箱型突破／底底高／上漲支撐 0~20，反彈／累積上漲 0~50；最多一位小數 |
| `days` | 回看窗口天數 | 僅累積上漲可帶；整數 1~90；省略為 20 |
| `requireRise` | 反彈漲段開關 | 僅反彈可帶；省略為 true；為 false 時不得帶 `riseDays`／`risePercent` |
| `dropDays` | 跌段回看天數 | 僅反彈可帶；整數 1~90；省略為 3 |
| `dropPercent` | 跌幅門檻 | 僅反彈可帶；0~50，最多一位小數；省略為 10 |
| `riseDays` | 反彈窗口天數 | 僅反彈且 `requireRise` 為 true 時可帶；整數 1~90；省略為 1 |

### 掃描範圍與區間

| Field | Type/Role | Rule |
|---|---|---|
| `stockIds` | 指定股票清單 | 省略或空陣列＝全市場在市股票；上限 200 檔，超過拒絕不截斷；清單中允許已下市股票與非普通股 |
| `commonStocksOnly` | 普通股篩選 | 省略視為 true；只留代號恰 4 位數字且首字元非 0 的股票；`stockIds` 有值時本欄不生效；只影響掃描母體，不寫入任何資料表 |
| `startDate` / `endDate` | 掃描區間 | 皆省略時為「今日往前一個日曆月～今日」；`startDate` 不得晚於 `endDate` |

### 命中項目（`items[]`）與同層清單

| Field | Type/Role | Rule |
|---|---|---|
| `stockId` / `stockName` | 股票識別 | 依實際命中股票回報 |
| `signalDate` | 訊號日 | 型態成立所依據的那一天；上漲支撐固定為起漲日 D；同一檔區間內多次命中只回報最近一次 |
| `buyDate` | 進場日 | 型態確認完成、可據以買進的交易日；上漲支撐為 D+2（`detail.confirmCloses` 最後一筆的交易日，依相鄰資料列認定、不以日曆日推算），其餘四個型態等於 `signalDate`；一律由掃描本身認定，呼叫端與回測端皆不推算 |
| `detail` | 型態明細 | 依型態不同結構不同（如箱高、擺動低點序列、支撐收盤、谷底/高點等） |
| `insufficientData` | 前置資料不足清單 | 與 `items`／`matchedCount` 互斥，代表「資料不夠、沒掃」 |
| `pendingConfirm` | 待確認清單 | 僅箱型突破（`confirmBars=2`）與上漲支撐可能非空；反彈與累積上漲恆為空陣列 |

## 限制條件

- 本模組只讀行情，不落地任何掃描結果；同一組行情換參數就是另一組答案，不存在「這列是用哪組參數算的」問題。
- `risePercent` 上限逐型態認定，不是全系統一個值：箱型突破／底底高／上漲支撐為 0~20，反彈／累積上漲為 0~50；超限即拒絕，不受理後回零命中。
- 一個必然不可能命中的請求要被拒絕，不能被受理後回零命中——零命中與參數填錯在畫面上無法分辨。
- `stockIds` 上限 200 檔，超過即拒絕；這個上限只綁使用者自行輸入的清單，不可與回測端的上限共用同一個常數。
- 底底高的擺動低點與遞增幅度判定一律以 5 日收盤均線（MA5）為準，原始最低價只回報供對照，不參與任何判定；平滑天數固定為 5，不隨靈敏度改變、也不可由呼叫端指定。
- 上漲支撐的確認長度固定 2 個交易日，不隨靈敏度改變、也不受 `risePercent` 覆寫影響；不驗證量能，是有意的設計而非遺漏。
- 上漲支撐的訊號日（起漲日 D）與進場日（D+2）刻意不同：型態要到 D+2 收盤才確認成立，以訊號日買進等於使用未來兩天的收盤價挑股票。
- 反彈的漲段窗口未跑滿也照樣判定，只要已達標即命中，不列入 `pendingConfirm`；反彈與累積上漲兩者皆不產生 `pendingConfirm`。
- 累積上漲 `days = 1` 為合法值但幾乎不會命中（窗口漲幅恆為 0%），這是型態定義的必然結果而非缺陷。
- 前置資料不足與「掃過沒型態」必須分開回報（`insufficientData` vs 未命中），不得混為一談。
- 型態判定一律以相鄰交易日比較，不因停牌造成的日曆間隔做任何插補。

## 跨主題規則

- 普通股篩選（`commonStocksOnly`）與代號判斷規則沿用同一套「只收普通股」定義，不得另立第二套判斷（見 stock-universe-import.md）。
- 上漲支撐的 `buyDate`（D+2）由本模組認定並回報，回測端據此原樣買進、不重新推算進場日，也不接受訊號日作為輸入（見 strategy-backtest.md）。

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| GET | /api/strategies | 取得可用策略清單與各策略的靈敏度／參數說明，供前端動態畫出設定卡片 | Direct（純查詢，不寫入任何資料，無需送審） |
| POST | /api/strategies/scan | 依指定型態、參數與股票範圍執行一次型態掃描，即時回報命中清單與各筆的訊號日、進場日 | Direct（純查詢／即時運算，不寫入任何資料，無需送審） |
