# 策略型態掃描 API

這個 API 讓使用者針對股票的日線行情做「型態偵測」，掃描指定期間內哪些股票出現了底底高、箱型突破、上漲支撐、反彈或累積上漲等型態，並回報命中清單。整個模組只做查詢與即時運算，不會把偵測結果落地存檔——同一批行情只要換一組判定參數就是另一組答案，因此每次請求都是重新掃描，不是讀取先前存好的結果，也沒有任何送審或核准流程。掃描母體預設只含上市普通股，也可由使用者指定股票清單或放寬到含 ETF／特別股等；掃描區間預設為近一個月，亦可自訂。回應內容一律以「命中／訊號／型態」表述，不得出現任何暗示買賣操作的措辭。

## 欄位定義

**策略目錄項**（`GET /api/strategies` 回應中的每一筆型態）

| Field | Type/Role | Rule |
|---|---|---|
| code | 字串／型態代碼 | 五種之一：`BOX_BREAKOUT`／`HIGHER_LOWS`／`RISING_SUPPORT`／`REBOUND`／`CUMULATIVE_RISE` |
| name | 字串／顯示名稱 | 中文名稱，供前端顯示 |
| presets | 陣列／靈敏度清單 | 有靈敏度的四個型態（箱型突破、底底高、上漲支撐、反彈）固定回三筆（嚴格／標準／寬鬆），每筆含代碼、名稱與說明文字；累積上漲固定回空陣列 |
| params | 陣列／可輸入參數清單 | 僅累積上漲提供，列出回看天數、漲幅門檻兩個參數，每筆含代碼、名稱、單位、預設值、範圍與調整級距；其餘四個型態不提供此欄位或為空陣列 |
| description | 字串／型態層級說明 | 僅累積上漲提供，作為卡片顯示文字的來源；有靈敏度的型態沒有此欄，其卡片說明文字改取自目前選定那段靈敏度自己的說明 |

**策略選擇**（`POST /api/strategies/scan` 請求中 `strategies[]` 的每一筆）

| Field | Type/Role | Rule |
|---|---|---|
| code | 字串／必填 | 五種型態代碼之一；同一次請求不得重複指定同一型態 |
| preset | 字串／視型態而定 | 嚴格／標準／寬鬆三擇一；箱型突破、底底高、上漲支撐、反彈四者必填；累積上漲不得帶此欄 |
| days | 整數／僅累積上漲可帶 | 回看窗口的交易日數，範圍 1～90；其餘四個型態帶了視為不合法；省略時採用預設值 20 |
| risePercent | 數值／選填 | 覆寫該策略的漲幅（對反彈而言是跌幅）門檻；範圍 0～50，最多一位小數；省略則沿用該靈敏度或預設值 |

**策略掃描結果**（`POST /api/strategies/scan` 回應中 `results[]` 的每一筆）

| Field | Type/Role | Rule |
|---|---|---|
| strategy | 字串 | 對應請求中的型態代碼 |
| preset | 字串／有靈敏度型態才有 | 該策略實際採用的靈敏度段落；累積上漲不含此欄 |
| days | 整數／僅累積上漲才有 | 該次掃描實際採用的回看天數（請求省略時回預設值 20）；其餘四個型態不含此欄 |
| matchedCount | 整數 | 命中檔數，等於 `items` 筆數 |
| items | 陣列 | 命中清單，每檔股票在區間內取最近一次命中的紀錄 |
| insufficientData | 陣列 | 前置行情不足以完成判定的股票代號；與命中互斥 |
| pendingConfirm | 陣列 | 已符合前段條件、但確認資料尚未到齊的股票代號；反彈與累積上漲兩型態恆為空陣列 |

## 限制條件

**策略目錄**

- 累積上漲沒有靈敏度可選，`presets` 固定回空陣列，改以策略層級的說明與參數清單描述
- 有靈敏度的四個型態維持固定三段（嚴格／標準／寬鬆），本次改動未變更其結構或說明文字

**掃描請求與結果**

- 累積上漲請求不得帶 `preset`，違反即拒絕並說明原因（400）
- 累積上漲以外的型態不得帶 `days`，違反即拒絕並說明原因（400）
- `days` 僅接受 1～90 之間的整數，非整數或超出範圍即拒絕並說明原因（400）
- 天數為 1 時窗口只有當天，累積漲幅恆為 0%，除非漲幅門檻也是 0 否則不會有任何命中——這是合法輸入，不是錯誤
- 有靈敏度的四個型態仍必須帶 `preset`，缺漏即拒絕並說明原因（400）
- `risePercent` 範圍固定為 0～50、最多一位小數，五個型態共用同一條驗證規則，只是各自覆寫的目標欄位不同（箱型突破的突破幅度、底底高每段遞增門檻、上漲支撐的單日漲幅、反彈的跌幅、累積上漲的漲幅門檻）
- 回應中 `preset` 與 `days` 互斥：有靈敏度的型態只回 `preset`，累積上漲只回 `days`
- 反彈與累積上漲不做事後確認，`pendingConfirm` 恆為空陣列
- 同一次請求同一型態代碼不得重複出現，違反即拒絕並說明原因（400）
- 指定股票清單上限 200 檔，超過即拒絕而非截斷
- 掃描母體篩選（`commonStocksOnly`）只影響掃描母體，不寫入任何資料表，也不改變股票主檔或股票總覽顯示的檔數
- 指定股票清單時，該清單允許包含已下市或非普通股，且不套用母體篩選

## 跨主題規則

- 普通股（掃描母體）的判斷邏輯沿用同一套「只收普通股」定義，不得各自實作第二份（見 stock-universe-import.md）
- 型態判定所需的日線行情來自個股每日價格資料，其累積起點與抓取方式由該規格定義；回看天數超過某檔可用行情長度時，該檔列為資料不足而非未命中（見 stock-price-ingestion.md）
- 型態判定一律以相鄰交易日比較、不因停牌造成的日曆間隔做插補，此規則須與指標統計保持一致（見 stock-indicator-statistics.md）
- 指定股票清單時，代號須存在於股票主檔，否則拒絕並列出不存在的代號（見 stock-catalog.md）

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| GET | /api/strategies | 查詢目前支援的型態清單，含各型態的靈敏度段落或可輸入參數，供前端動態產生策略選單 | Live direct |
| POST | /api/strategies/scan | 依指定的型態、靈敏度或自訂參數，即時掃描股票行情並回報命中清單 | Live direct |
