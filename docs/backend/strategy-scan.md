# 策略型態掃描 API

這個模組讓使用者針對股票的日線行情做「型態偵測」，目前支援箱型突破、底底高、上漲支撐、反彈、累積上漲五種型態，找出在指定期間內出現特定價格行為的股票。掃描是即時計算、不落地任何結果，因為型態的判定完全由使用者傳入的參數決定，同一批行情換一組門檻就是不同答案，把結果存下來反而會產生「這筆是用哪組參數算的」的疑慮。其中箱型突破、底底高、上漲支撐三個型態各提供三段靈敏度預設，並允許使用者自行覆寫其漲幅門檻；反彈與累積上漲則完全由使用者自行輸入所有參數。掃描母體預設只涵蓋上市普通股（可切換為包含 ETF／特別股／TDR 等全部在市股票），掃描區間預設近一個月，皆可自訂。所有回應一律以「命中／訊號／型態」表述，不得出現任何暗示操作建議的措辭。

## 欄位定義

**掃描請求（頂層）**

| Field | Type/Role | Rule |
|---|---|---|
| `strategies` | 陣列，必填 | 至少一筆；同一策略代碼不得重複出現 |
| `stockIds` | 字串陣列，選填 | 省略或空陣列＝掃描全部在市股票；上限 200 檔，超過即拒絕（不默默截斷）；使用者明確指定清單時，允許含已下市股票與非普通股，且不受 `commonStocksOnly` 過濾 |
| `commonStocksOnly` | 布林，選填 | 省略時視為 `true`；只留代號恰為 4 位數字且首字元非 `0` 的普通股；`stockIds` 有值時本欄位不生效；只影響掃描母體，不寫入任何資料表 |
| `startDate` | 日期，選填 | 省略時為 `endDate` 往前一個日曆月；不得晚於 `endDate` |
| `endDate` | 日期，選填 | 省略時為今日 |

**策略選擇（`strategies[]` 每一筆）**

| Field | Type/Role | Rule |
|---|---|---|
| `code` | 字串，必填 | 五選一：箱型突破／底底高／上漲支撐／反彈／累積上漲 |
| `preset` | 字串，視型態而定 | 箱型突破／底底高／上漲支撐必填（嚴格／標準／寬鬆三選一）；反彈與累積上漲不得帶此欄位 |
| `risePercent` | 數值，選填 | 幅度門檻，最多一位小數；**合法範圍逐型態認定**：箱型突破／底底高／上漲支撐為 `0`~`20`，反彈／累積上漲為 `0`~`50`。對有靈敏度的三個型態，是覆寫該靈敏度的漲幅門檻（省略則沿用靈敏度原值）；對累積上漲，是窗口內累積漲幅門檻（省略為 15）；對反彈，是自谷底起算的反彈幅度門檻（省略為 5，且 `requireRise` 為否時不得帶） |
| `days` | 整數，選填 | 只有累積上漲接受；回看窗口的交易日數，範圍 `1`~`90`，省略為 20；其餘型態帶了視為無效 |
| `requireRise` | 布林，選填 | 只有反彈接受；是否另外要求反彈幅度達標，省略為是；為否時不得再帶 `riseDays`／`risePercent` |
| `dropDays` | 整數，選填 | 只有反彈接受；跌段回看交易日數，範圍 `1`~`90`，省略為 3 |
| `dropPercent` | 數值，選填 | 只有反彈接受；跌幅門檻，範圍 `0`~`50`，最多一位小數，省略為 10 |
| `riseDays` | 整數，選填 | 只有反彈接受，且 `requireRise` 為是時才可帶；反彈窗口交易日數，範圍 `1`~`90`，省略為 1 |

**掃描結果（`results[]` 每一筆）**

| Field | Type/Role | Rule |
|---|---|---|
| 型態代碼 | 字串 | 對應請求中的型態；`results` 依請求送入的順序回傳，一個型態一筆 |
| 本次採用的參數 | 依型態而定 | 原樣回報該型態**實際採用**的值（省略時回預設值）：有靈敏度的三個型態回靈敏度；累積上漲回天數；反彈回是否要求反彈段、跌段天數與跌幅門檻，要求反彈段時另回反彈天數與反彈幅度。靈敏度與這些參數欄位不會同時出現 |
| `matchedCount` | 整數 | 命中檔數，等於命中清單筆數 |
| `items` | 陣列 | 命中清單；同一檔在區間內多次命中只回報最近一次，依訊號日由新到舊排序，同日依代號升冪 |
| `insufficientData` | 陣列 | 前置行情不足以完成判定的股票代號；與命中互斥 |
| `pendingConfirm` | 陣列 | 已符合前段條件、確認資料尚未到齊的股票代號，不計入命中檔數；只有箱型突破與上漲支撐可能非空，反彈與累積上漲恆為空陣列 |

## 限制條件

**掃描請求**

- `stockIds` 省略或空陣列時，母體為在市股票再依 `commonStocksOnly` 過濾；有值時視為使用者明確指名，一律不套用 `commonStocksOnly`，也允許已下市股票與非普通股
- `stockIds` 上限 200 檔，超過即拒絕，不會靜默截斷
- `commonStocksOnly` 只影響本次掃描母體，不寫入或變更任何資料
- `startDate` 不得晚於 `endDate`

**策略選擇**

- 同一次請求可同時送入多個型態，但同一型態代碼不得重複
- 有靈敏度的三個型態（箱型突破／底底高／上漲支撐）必填靈敏度；無靈敏度的兩個型態（反彈／累積上漲）不得帶靈敏度
- 每個型態專屬的參數（累積上漲的天數、反彈的四個參數與反彈段開關）只能用在對應型態，帶到不適用的型態視為請求錯誤，並在錯誤中指名是哪個型態的哪個欄位
- **`risePercent` 的合法上限不是全系統一個值，而是逐型態認定**：箱型突破／底底高／上漲支撐為 `0`~`20`；反彈／累積上漲為 `0`~`50`。上限分兩級是因為這五個值量的不是同一件事——上漲支撐量的是**單日**漲幅，而台股單日漲跌幅限制為 10%，允許填 30 只會讓使用者送出一個在規則上不可能命中的掃描；箱型突破的突破幅度與底底高的每段遞增幅度到 20% 以上也已不是該型態在描述的行為。超出範圍直接拒絕整個請求並指名超限的型態，不會被受理後回零命中
- `risePercent` 最多一位小數；為 `0` 時代表該型態不驗證漲幅（即最寬鬆設定），不是關閉整個型態
- 反彈的 `dropPercent` 上限維持 `0`~`50` 不變，理由與反彈的 `risePercent` 相同
- 反彈的反彈段開關為否時，不得再帶反彈天數與反彈幅度
- 累積上漲的天數為 1 是合法輸入，但窗口只有當天、累積漲幅恆為 0%，除非漲幅門檻也是 0 否則不會有命中；反彈的跌段天數為 1 同理

## 跨主題規則

- 掃描母體的普通股篩選（代號恰為 4 位數字、首字元非 `0`）沿用同一套判斷邏輯，兩處不得各自實作一份（見 stock-universe-import.md）
- 型態判定所需的日線行情取自既有已入庫的價格資料，本模組只讀不寫（見 stock-price-ingestion.md）
- 指定股票清單時，代號須存在於股票主檔，掃描母體的在市狀態亦以股票主檔為準（見 stock-catalog.md）
- 型態判定一律以相鄰交易日比較、不對停牌造成的日曆間隔做插補，此規則須與指標統計保持一致（見 stock-indicator-statistics.md）

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| GET | /api/strategies | 取得可用型態清單、各型態的靈敏度說明或可輸入參數範圍，供前端畫出策略卡片 | Live direct |
| POST | /api/strategies/scan | 依選定的型態、參數與掃描範圍即時執行型態偵測，回報命中清單（純查詢，不落地任何結果） | Live direct |
