# 模擬交易持股 API

這支 API 讓使用者用最少的輸入記下「假設我在某天以當天價格買了一張，現在賺賠多少」。查詢一律讀取目前最新的行情，現價、未實現損益、報酬率都在查詢當下即時算出，不會存起來。新增與刪除持股都立即生效，不經審核。買進價一定由系統從那一天的實際行情取得，使用者只能選日期，不能自填價格。列表可帶「目標結算日」，並以該日之前的最高價另外算出一組結算損益。這個日期若不是交易日，系統會自動改用距離它最近的全市場交易日，回應中也會回報改過後的日期。

## 欄位定義

**模擬持股（新增請求）**

| Field | Type/Role | Rule |
|---|---|---|
| stockId | 字串，必填 | 前後空白去除後比對，必須是系統已有的股票（已下市者也可） |
| buyDate | 日期，選填 | 不得晚於今日；省略時取該檔最後一個有收盤價的交易日（僅限以收盤價買進）；指定的日子必須正好有該檔行情，否則拒絕 |
| priceBasis | 字串，選填 | 只能是收盤價（預設）或開盤價；選開盤價時必須同時指定買進日 |
| 股數 | 系統固定值 | 恆為 1000 股（1 張），不可指定 |
| 買進價 | 系統取得 | 取買進日當天的收盤價或開盤價（依買進價基準），必須大於 0，不可由使用者輸入 |

**模擬持股（列表中每一筆）**

| Field | Type/Role | Rule |
|---|---|---|
| id | 整數，識別碼 | 刪除時使用 |
| stockId / stockName | 字串 | 名稱取自股票主檔 |
| buyDate / buyPrice / shares | 日期／數字／整數 | 建立時寫入，原樣回報，之後不再變動 |
| buyFee / sellFee / sellTax / cost | 整數（元） | 手續費與證交稅各自無條件捨去至元；成本為買進金額加買進手續費 |
| currentDate / currentPrice | 日期／數字 | 該檔最新一個有收盤價的交易日及其收盤價；可能早於今日 |
| unrealizedProfit | 整數（元） | 以現價假設今日賣出，已扣賣出手續費與證交稅；可為負值，不夾為 0 |
| returnPercent | 數字 | 未實現損益占成本的百分比，兩位小數；可為負值 |
| settlement | 物件或空值 | 未帶目標結算日，或買進日晚於目標結算日時為空 |
| settlement.sellDate / sellPrice | 日期／數字 | 買進日至目標結算日（含兩端）之間最高價，及其第一次出現的交易日 |
| settlement.sellFee / sellTax | 整數（元） | 以結算賣出價計算，與現價損益同一套成本 |
| settlement.profit / returnPercent | 整數／數字 | 結算損益與報酬率（兩位小數），可為負值 |

**列表彙總（整體回應）**

| Field | Type/Role | Rule |
|---|---|---|
| asOfDate | 日期 | 本次查詢的今日 |
| defaultBuyDate | 日期或空值 | 全市場上一次收盤日，供畫面預設；完全沒有行情時為空 |
| lotSize / feeRatePercent / taxRatePercent | 固定值 | 1000 股／0.1425%／0.3%，供畫面說明用 |
| totalCost / totalUnrealizedProfit | 數字 | 各筆加總；無持股時為 0 |
| totalReturnPercent | 數字或空值 | 以成本加權，無持股時為空（不是 0） |
| settleDate | 日期或空值 | 實際採用的目標結算日，即請求日期換成最近交易日之後的結果；未帶時為空 |
| settledTotalCost / settledTotalProfit | 數字 | 只加總有結算的各筆；沒有任何一筆有結算時為 0 |
| settledTotalReturnPercent | 數字或空值 | 以成本加權，沒有任何一筆有結算時為空 |

## 限制條件

- 股數固定為 1 張（1000 股），買進價不可由使用者填寫，只能由買進日實際行情決定。
- 買進價寫入後不再變動，即使事後來源更正該日價格，這筆持股的成本也不變。
- 買進日不得晚於今日；指定日期沒有該檔行情（停牌、未上市、價格為 0、非交易日）時一律拒絕，不會自動改用鄰近交易日。
- 以開盤價買進必須同時指定買進日，省略買進日的預設只適用於收盤價。
- 同一檔股票在同一買進日只能有一筆；重複加入會被拒絕，不會覆蓋，也不論兩次選的價格基準是否相同。
- 目標結算日不得晚於今日；此檢查針對使用者請求的原始日期，先驗證，再換成交易日。
- 目標結算日一律換成距離請求日期最近的全市場交易日：本身是交易日就用本身；前後等距時取較早的一天；不會晚於全市場最後一個交易日；資料庫完全沒有行情時照原日期使用。
- 結算窗口含買進日與目標結算日兩端；買進日晚於目標結算日的持股沒有結算，不計入結算總計，但仍列在清單並計入現價總計。
- 結算不取代現價：帶了目標結算日，現價與未實現損益照常回報。
- 目標結算日只是單次查詢的參數，不會被儲存。
- 已下市的股票照常列出並計入彙總，現價取它最後一個有成交的交易日。
- 列表依買進日由新到舊排序，同日依股票代號由小到大；沒有任何持股時回傳空清單，不算錯誤。
- 三支 API 都不抓取外部資料，也不寫入股票主檔或行情資料。
- 刪除的對象必須存在，否則回報找不到。

## 跨主題規則

- 建立持股時，股票代號必須存在於股票主檔，已下市者亦可，錯誤代碼與策略掃描一致（見 stock-catalog.md、strategy-scan.md）。
- 買進價與現價取自每日行情；價格為 0 的日子視為「當天沒有成交」，不當作行情（見 stock-price-ingestion.md、strategy-backtest.md）。
- 手續費、證交稅與捨去規則與策略回測完全同一套；加權彙總的理由也相同（見 strategy-backtest.md）。
- 以開盤價建立持股時，買進價必須與策略回測在同一日的買進價一致，供策略分頁「加入模擬」使用（見 strategy-backtest.md）。
- 預設買進日與「交易日」的定義以全市場每日行情為準，不論個別股票是否停牌或下市（見 stock-price-ingestion.md）。
- 持股資料的儲存與唯一性由資料表規格定義（見 specs/dba/simulated-trade.md）。

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| GET | /api/simulated-trades | 列出所有模擬持股及其未實現損益；可帶目標結算日，另外回報結算損益與彙總 | Live direct |
| POST | /api/simulated-trades | 以指定買進日（預設為最後收盤日）新增一筆 1 張的模擬持股 | Direct |
| DELETE | /api/simulated-trades/{id} | 刪除一筆模擬持股 | Direct |
