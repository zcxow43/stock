# 上市股票 universe 匯入 API

這支 API 用一次對外部資料源的請求，把台股上市普通股的代號與名稱整批寫進股票主檔，藉以先把「有哪些股票」建置起來，之後才由使用者另外觸發行情回補。異動不經送審，呼叫成功即直接套用到正式資料；同一請求內只做代號與名稱的新增或更新，完全不寫入任何行情資料。若資料源當次沒有回傳可用資料，一律視為失敗並整批放棄寫入，不會留下部分匯入的狀態。

## 欄位定義

**股票（stock，僅本 API 涉及之欄位）**

| Field | Type/Role | Rule |
|---|---|---|
| 股票代號（stock_id） | 識別鍵 | 僅收「恰為 4 碼數字、且首碼非 0」的代號；其餘一律略過並計入略過檔數，不寫入 |
| 股票名稱（stock_name） | 基本資料 | 取自資料源並去除前後空白；名稱為空白者視同不合格，略過不寫入；既有股票的名稱一律以本次匯入結果覆蓋更新 |
| 市場別（market） | 分類值 | 新股票固定寫入「上市（TSE）」；既有股票的市場別本 API 一律不變動 |
| 是否上市中（is_active） | 狀態旗標 | 新股票固定寫入「上市中」；既有股票的此狀態本 API 在任何情況下都不變動，不會因為本次沒出現在資料源清單中就判定下市，也不會把人工下市過的股票自動改回上市中 |

## 限制條件

- 只收「恰為 4 碼數字、且首碼非 0」的代號，判定為一般個股；ETF、特別股、TDR／存託憑證、REIT 一律略過，不列入母體。
- 名稱經去除前後空白後仍為空字串者，視為不合格資料，略過不寫入。
- 既有股票只允許更新名稱，市場別與上市中狀態一律不可被本 API 變動（不論往哪個方向）。
- 資料源當次沒有回傳任何可用資料（空清單，或篩選後一檔合格個股都沒有）時，本次視為失敗，不對股票主檔做任何寫入。
- 資料源連線失敗、逾時或回應無法解析時，同樣視為失敗，不做任何部分寫入；一律要先完整取得並確認資料合格後才進入寫入階段。
- 本 API 為單次、同步性質的短作業，不建立進度追蹤紀錄，也不與其他長時間作業互斥執行。

## 跨主題規則

- 股票的上市／下市狀態一律只能由人工透過下市或復市操作變更，本 API 完成匯入後不會、也不允許改動任何股票既有的上市中狀態（見 stock-catalog.md）。
- 本 API 建立或更新的股票清單，是後續全市場行情回補與全市場策略掃描判斷母體範圍的依據；本次新加入的股票要等到下一次回補作業啟動時才會被納入回補與掃描範圍（見 stock-price-ingestion.md、strategy-scan.md）。
