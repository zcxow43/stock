# 上市股票 universe 匯入 API

這支 API 是「更新股票清單」動作的實作：一次向交易所公開資料取得全體上市普通股的代號、名稱與官方產業別，直接更新股票主檔與產業別對照資料，完全不寫入任何行情資料。異動一經呼叫即直接生效於主檔，不經任何審核流程；股票的下市與復市則不在此 API 範圍內，仍需人工操作另一支功能處理。整支 API 對外只發出兩次固定的資料請求，不逐檔查詢、不涉及分批進度追蹤。

## 欄位定義

### 股票主檔（受本 API 影響的欄位）

| Field | Type/Role | Rule |
|---|---|---|
| 股票代號 | 唯一識別 | 只有恰為 4 個數字字元、且首字元不為 0 的代號才會被寫入（僅普通股），其餘一律略過並計入略過檔數 |
| 股票名稱 | 顯示名稱 | 每次匯入以來源最新值覆蓋更新；名稱為空字串的資料列視同不合格，略過不寫入 |
| 上市市場別 | 固定值 | 新增列固定寫入「上市」；既有列的市場別本 API 不會更動 |
| 在市狀態 | 是否在市 | 新增列固定為「在市」；既有列的在市狀態本 API **在任何情況下都不會變動**（不會自動下市，也不會自動復市） |

### 產業別

| Field | Type/Role | Rule |
|---|---|---|
| 產業別名稱 | 唯一鍵 | 以中文名稱作為識別依據（來源未提供穩定代碼）；比對不到既有名稱時新增一筆，已存在者代碼不變 |

### 股票產業別關聯

| Field | Type/Role | Rule |
|---|---|---|
| 股票代號 | 關聯鍵 | 僅限本次資料源涵蓋到、且通過普通股篩選、且已存在於股票主檔的股票才會被處理 |
| 產業別代碼 | 關聯鍵 | 對應本次匯入解析出的產業別 |
| 關聯內容 | 整組取代 | 對本次來源涵蓋到的股票，先刪除其既有全部關聯、再寫入本次取得的關聯；未被本次來源涵蓋到的股票，其既有關聯完全不動 |

### 回應（整體）

| Field | Type/Role | Rule |
|---|---|---|
| `fetchedCount` | 來源清單總列數 | 篩選前的原始筆數 |
| `eligibleCount` | 通過普通股篩選檔數 | — |
| `skippedCount` | 被篩掉檔數 | 等於 `fetchedCount − eligibleCount` |
| `insertedCount` | 本次新增列數 | — |
| `updatedCount` | 本次命中既有列並更新的檔數 | 名稱即使相同仍計入 |
| `totalActiveCount` | 匯入後在市股票總數 | — |
| `industrySourceStatus` | 產業別來源狀態 | `OK` / `UNAVAILABLE` / `EMPTY` / `MALFORMED`；非 `OK` 時代表本次完全跳過產業別寫入階段 |
| `industryCount` | 匯入後產業別總數 | 來源非 `OK` 時為寫入前的既有值 |
| `industryLinkedStockCount` | 至少有一筆產業別關聯的在市股票數 | — |
| `uncategorizedStockCount` | 完全無產業別關聯的在市股票數 | 等於 `totalActiveCount − industryLinkedStockCount`；用來讓使用者一眼看出未分類規模的成因 |

## 限制條件

### 股票主檔

- 無請求參數，範圍固定為上市普通股全體，不可調整。
- 只收恰為 4 個數字字元且首字元不為 0 的代號；ETF、特別股、TDR、REIT 等一律略過。
- 既有列僅更新名稱；在市狀態與市場別為不可變動欄位，兩個方向（下市↔復市）皆不受本 API 影響。
- 來源清單為空陣列時，整支 API 以錯誤結束（502），不視為「成功匯入 0 檔」，且不對任何資料做部分寫入。

### 產業別與關聯

- 產業別的寫入僅由本 API 負責，其他行情相關的匯入動作不維護此資料。
- 產業別來源（第二個資料源）發生任何失敗，都不會讓整支 API 失敗，僅記錄狀態並完全跳過產業別寫入階段，既有產業別資料原封不動。
- 「整組取代」的範圍嚴格限制在本次來源涵蓋到的股票，不得對整份關聯資料重建，以避免單次來源異常波及未受影響的股票。
- 產業別關聯寫入必須在股票主檔與產業別兩者皆完成新增／更新之後才進行。

### 併發

- 本 API 為同步短作業，不使用批次進度的併發鎖，因此可與進行中的全市場行情回補同時執行；新增股票僅會在下一次回補時才被回補行情。

## 跨主題規則

- 股票的下市與復市（在市狀態的變更）一律由股票清單管理的刪除／回復操作處理，本 API 完全不涉及（見 [stock-catalog.md](stock-catalog.md)）。
- 本 API 建立的「在市股票」範圍是全市場行情回補、型態掃描與漲幅排行的母體依據，該範圍需先由本 API 建立，其他功能才能涵蓋到完整標的（見 [stock-price-ingestion.md](stock-price-ingestion.md)、[strategy-scan.md](strategy-scan.md)）。
- 本 API 建立的產業別對照是漲幅排行分組顯示的唯一來源；產業別來源失敗而跳過寫入時，該功能的未分類數量會相應偏高（見 [industry-gain-ranking.md](industry-gain-ranking.md)）。
- 本 API 刻意不寫入任何行情，行情回補依賴逐日連續無缺口的資料才能正確地遞迴推算技術指標，需另外呼叫回補動作補齊（見 [stock-price-ingestion.md](stock-price-ingestion.md)）。
- 每日行情增量雖同樣會維護股票主檔，但不維護產業別資料，避免多條路徑各自更新同一份分類資料而失去一致性（見 [stock-price-ingestion.md](stock-price-ingestion.md)）。

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
