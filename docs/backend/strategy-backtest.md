# 策略命中回測 API

這支 API 把「掃描出來的命中清單」換算成一份回測結果：假設在每檔的訊號日收盤買進，之後在到今天為止的區間內以最高開盤價賣出，回報每一檔的賣出日、報酬率、收益，並彙總整份清單的總報酬率與總收益。它不判定任何型態、不對外抓取任何行情，只讀取系統既有的每日價格資料做四則運算；回測結果本身不落地保存，每次呼叫都是即時重新計算，因此也沒有送審或核准的概念——查詢即結果，直接回傳。

## 欄位定義

### 一筆回測結果（items 中的一檔）

| Field | Type/Role | Rule |
|---|---|---|
| stockId | 字串，標的識別 | 對應請求中同一檔的代號 |
| signalDate | 日期，輸入回顯 | 該檔的訊號日，與請求一致 |
| buyPrice | 數值，可為 null | 訊號日收盤價；訊號日當天沒有該檔價格資料時為 null |
| sellDate | 日期，可為 null | 賣出窗口內最高開盤價第一次出現的交易日；無法回測時為 null |
| sellPrice | 數值，可為 null | 賣出窗口內開盤價的最大值；無法回測時為 null |
| returnPercent | 數值（百分比，兩位小數），可為 null，**可為負值** | (賣出價－買進價)÷買進價×100；無法回測時為 null |
| profit | 數值（元），可為 null，**可為負值** | (賣出價－買進價)×固定股數；無法回測時為 null |

### 一份回測彙總（回應整體）

| Field | Type/Role | Rule |
|---|---|---|
| asOfDate | 日期 | 本次回測窗口的迄日，即查詢當下的今日 |
| lotSize | 整數，固定值 | 每檔固定持有股數，恆為 1000，用來讓收益單位可被解讀 |
| totalCost | 數值 | 僅計入可回測標的的買進成本總和；無可回測標的時為 0 |
| totalProfit | 數值 | 僅計入可回測標的的收益總和；無可回測標的時為 0 |
| totalReturnPercent | 數值，可為 null | 總收益÷總成本×100，成本加權而非逐檔報酬率平均；無可回測標的時為 null（非 0） |
| backtestedCount | 整數 | 實際計入彙總的標的數（賣出日有值的筆數），與清單筆數之差即為無法回測的檔數 |
| items | 陣列 | 逐檔回測結果，順序與請求順序一致，不重新排序 |

## 限制條件

- 賣出窗口從訊號日的**次一交易日**起算，不含訊號日當天——因為買進價已用訊號日收盤價，若窗口把訊號日自己的開盤也算進去，會出現「下午三點才買進、卻賣在當天早上九點」這種時序上不可能成立的交易。
- 報酬率與收益**不得夾住負值**：最高開盤價仍可能低於買進價，此時如實回報負值，不得改成 0、不得視為不賣出、不得改挑其他日子出場，否則這份回測會變成一個永遠不會虧錢的失真工具。
- **無法回測的標的仍留在結果清單中**，只是不計入總成本與總收益——不得因為算不出來就把該檔從結果裡拿掉，否則彙總數字會被誤讀成涵蓋了全部標的。
- **總報酬率是以成本加權計算，不是各檔報酬率的算術平均**：因為每檔固定持有一張，高價股與低價股的成本可相差數十倍，兩個數字本來就會不一致，這是刻意的設計而非誤差。
- 明列的已知限制：價格是原始成交價，**未經除權息還原**，有除權息事件的標的報酬率會系統性偏低；**不計任何交易成本**（手續費、證交稅、滑價）；**不做部位管理**（不考慮資金上限、同時持股數、先賣先買），本質是一份「逐檔最高開盤價出場」的統計，不是交易策略績效模擬。

## 跨主題規則

- 回測的輸入清單（標的與訊號日）來自策略掃描的命中結果，一檔股票命中多個策略時要取哪一個訊號日、以及 `items` 的排序，都是呼叫端依掃描結果決定的，本 API 不重排（見 strategy-scan.md）。
- `TOO_MANY_STOCKS` 與 `UNKNOWN_STOCK_ID` 兩個錯誤情形沿用掃描端點已定義的同名錯誤碼與回應形狀，同一畫面對同一種錯誤不使用兩套代碼（見 strategy-scan.md）。
- 買進價與賣出價候選皆讀自每日價格資料；停牌日因為沒有對應列而自然不會被選為賣出日，這是延續價格資料「不得補零」的約定所帶來的結果（見 stock-price-ingestion.md）。
- 標的代號存在性檢查不篩已下市狀態，已下市股票一樣可以回測，此原則與掃描端點允許指定已下市股票一致（見 stock-catalog.md）。
