# 策略命中回測 API

這支 API 把一份掃描命中清單換算成「如果當時買了，到掃描區間結束為止最好能賣在哪裡」的結果。呼叫端送來每一筆命中的買進日，以及造成這份清單的那次掃描的迄日。系統以買進日的開盤價買進，在買進日之後到該迄日為止的窗口內，以最高開盤價賣出。收益與報酬率都已扣除買賣手續費與賣出時的證交稅，並彙總出整份清單的總報酬率與總收益。這是無狀態的純讀取運算：只讀系統已有的行情，不做型態判定，也不寫入或保存任何結果，每次呼叫都重新計算。

賣出窗口的迄日就是請求的 `endDate`，省略或晚於今日時以今日為準（`endDate` 不必是交易日），所以賣出日一定不晚於該檔在掃描區間內的最後一個交易日。回應的 `asOfDate` 就是這個實際使用的窗口迄日。窗口內沒有任何可賣出的交易日時，不算無法回測，改以買進日當天開盤價賣出（賣出日等於買進日）。下列三種情形的標的買不進去，該筆照常列在結果中，但欄位全空，也不計入彙總：
- 買進日當天沒有行情。
- 買進日當天的開盤價為 0。
- 買進日晚於窗口迄日。

這類標的不會造成整次回測失敗，賣出價低於買進價時負報酬也照實回報。請求本身有問題（清單為空、筆數過多、代號不存在、同一買進日重複、買進日缺漏或在未來）時，整份請求會被拒絕（400）。

## 欄位定義

**請求本體**

| Field | Type/Role | Rule |
|---|---|---|
| `endDate` | 日期，選填 | 賣出窗口的迄日，應為造成這份清單的那次掃描的迄日原值；可以不是交易日。省略或晚於今日時，以今日為窗口迄日 |
| `items` | 清單，必填 | 至少一筆，上限 20000 筆；計的是筆數而非檔數 |

**請求中的每一筆（`items[]`）**

| Field | Type/Role | Rule |
|---|---|---|
| `stockId` | 文字，必填 | 股票代號，必須是系統內已有的標的；已下市的標的照常可回測。同一代號可出現多次，只要買進日不同 |
| `buyDate` | 日期，必填 | 該筆的買進日，即掃描回報的進場日，由呼叫端原樣帶入、本 API 不推算；不得缺漏，也不得晚於今日 |

**回應整體（彙總）**

| Field | Type/Role | Rule |
|---|---|---|
| `asOfDate` | 日期 | 本次回測實際使用的窗口迄日：等於請求的 `endDate`；`endDate` 省略或晚於今日時為今日 |
| `lotSize` | 整數 | 每筆的股數，恆為 1000（1 張），讓呼叫端能解讀收益的單位 |
| `feeRatePercent` | 數字 | 手續費率，恆為 0.1425%，不打折 |
| `taxRatePercent` | 數字 | 證交稅率，恆為 0.3% |
| `totalCost` | 數字 | 所有可回測筆的成本加總（含買進手續費）；沒有可回測的筆時為 0 |
| `totalProfit` | 數字 | 所有可回測筆的收益加總；沒有可回測的筆時為 0 |
| `totalReturnPercent` | 數字或空值 | 總收益 ÷ 總成本 × 100，四捨五入至小數第二位；以成本加權，不是各筆報酬率的平均；沒有可回測的筆時為空值（不是 0） |
| `backtestedCount` | 整數 | 實際計入彙總的筆數；與清單筆數的差，就是無法回測的筆數 |
| `items` | 清單 | 順序與請求完全一致，不重新排序 |

**回應中的每一筆（`items[]`）**

| Field | Type/Role | Rule |
|---|---|---|
| `stockId` | 文字 | 股票代號，原樣帶回 |
| `buyDate` | 日期 | 買進日，原樣帶回；回應不含訊號日 |
| `buyPrice` | 數字或空值 | 買進日的開盤價；買進日沒有該檔行情、開盤價為 0，或買進日晚於窗口迄日時為空值 |
| `sellDate` | 日期或空值 | 窗口內最高開盤價第一次出現的交易日，不晚於 `asOfDate`；窗口為空時等於買進日；無法回測時為空值 |
| `sellPrice` | 數字或空值 | 窗口內的最高開盤價，可能低於買進價；窗口為空時等於買進價；無法回測時為空值 |
| `buyFee` | 整數或空值 | 買進手續費（元），無條件捨去；買進價為空值時為空值 |
| `sellFee` | 整數或空值 | 賣出手續費（元），無條件捨去；無法回測時為空值 |
| `sellTax` | 整數或空值 | 證交稅（元），無條件捨去；無法回測時為空值 |
| `cost` | 整數或空值 | 買進價 × 1000 加買進手續費（元）；買進價為空值時為空值 |
| `returnPercent` | 數字或空值 | 收益 ÷ 成本 × 100，兩位小數；可為負值；無法回測時為空值 |
| `profit` | 整數或空值 | 賣出金額扣除賣出手續費、證交稅與成本後的收益（元）；可為負值；無法回測時為空值 |

## 限制條件

- 唯一鍵是「股票代號加買進日」的組合，不是股票代號：
  - 一檔股票每有一個相異買進日就是獨立的一筆，各自佔 1 張、各自計入彙總。
  - 同一組合不得重複送出，即使造成它的是不同策略或不同訊號日；重複會被拒絕（400），不會被默默合併，去重是呼叫端的責任。
  - 請求與回應都不接受策略或訊號日欄位。
- 買進價固定是買進日的開盤價；賣出窗口從買進日的次一交易日起，到窗口迄日（含）為止，買進日本身不納入窗口。
- 賣出窗口的迄日由請求的 `endDate` 決定：
  - 賣出日最晚是該檔在窗口迄日當天或之前的最後一個交易日。
  - `endDate` 晚於今日時以今日為迄日。
  - 窗口迄日是過去的日期時，同一筆的結果不再隨今日變動；窗口迄日是今日時，退路的結果是暫時的，該檔多出交易日後重新回測就會改變。
- 無法回測共三種情形，三者一律使該筆所有結果欄位為空值、照常出現在回應中，且完全不計入彙總：
  1. 買進日當天沒有該檔行情。
  2. 買進日當天開盤價為 0。
  3. 買進日晚於窗口迄日。這種筆不走退路，也不會被改成較早的買進日。
- 窗口內沒有任何可賣出的交易日時，不是無法回測，而是以該檔最後一個交易日（此時即買進日）的開盤價賣出：
  - 費稅照常計算，並計入彙總。
  - 即使窗口迄日之後該檔已有交易日，也不使用那些交易日。
  - 退路只在窗口為空時啟用，不是賣出價的下限；窗口內只要有可賣出的交易日，就取最高開盤價，即使低於買進價。
  - 此時報酬率約 −0.58%，全是手續費與證交稅造成，不代表價格變動。
- 開盤價為 0 的日子視為沒有成交：不能當買點，也不列入賣出候選；窗口內若只剩這類日子，視同窗口為空。
- 負報酬必須如實回報，不得夾為 0，也不得改挑別的日子。賣出價等於買進價時收益仍為負，因為要付兩次手續費與一次證交稅。
- 交易成本只有三項，各自無條件捨去至元後再相加：
  - 買進手續費。
  - 賣出手續費。
  - 賣出時的證交稅（一律 0.3%，不依標的種類區分）。
  - 計算須用精確的十進位運算。
- 買進價與 `sellDate` 永遠同時有值或同時為空值。
- 彙總只計可回測的筆。總報酬率以成本加權，沒有可回測的筆時為空值，不是 0。
- 價格是未經除權息還原的原始成交價，有除權息事件的標的報酬率會系統性偏低；本回測也不計滑價、不做部位管理。
- 清單筆數上限 20000 是為了擋掉荒謬的請求體，不是產品規則；真的撞到時應調高上限，不得在前端截斷清單。上限不得與掃描的 200 檔上限共用。
- 價格必須以整份清單為條件、用有限次數的批次查詢取得，不得逐檔各查一次。
- 本 API 不寫入任何資料、不建立進度紀錄，結果不落地。

## 跨主題規則

- 買進日（進場日）的定義屬於型態本身，由掃描在每筆命中上回報，本 API 只負責「那天開盤買進」，不為任何型態做區分，也不推算買進日。掃描回報的買進日可以晚於掃描迄日，此時該筆無法回測（見 strategy-scan.md）。
- 窗口迄日沿用造成這份清單的那次掃描的迄日：呼叫端在掃描成功後自動接著送出回測，並原樣帶入該次掃描的 `endDate`（見 strategy-scan.md）。
- 價格資料完全來自每日行情；本 API 不對外抓資料，也不自行補值。停牌日沒有行情，自然不會成為買點或賣點（見 stock-price-ingestion.md）。
- 代號是否存在不過濾是否仍在上市，因此已下市的標的照常可回測，與掃描允許指定已下市股票一致（見 strategy-scan.md）。
- 清單過大與代號不存在使用與掃描相同的錯誤代碼和回應形狀，但門檻值不同：掃描綁的是使用者輸入的 200 檔，本 API 綁的是掃描輸出的 20000 筆（見 strategy-scan.md）。
