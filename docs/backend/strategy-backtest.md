# 策略命中回測 API

策略命中回測 API 把一份掃描命中清單換算成「如果當時照進場日買進，到今天為止最好能賣在哪裡」的結果。呼叫端送入每筆命中的股票代號與進場日（`buyDate`），系統以進場日收盤價買進、在其後至今日的區間內找出最高開盤價作為賣出點，逐筆回報買進價、賣出日、賣出價、報酬率與收益，並彙總出以成本加權的總報酬率與總收益。本模組不做任何型態判定，也不接受策略代碼或訊號日，只單純讀取既有行情做四則運算，因此是一個獨立、無狀態、可重複呼叫、不落地任何結果的端點；掃描完成後，前端會自動接著送出這個回測請求，畫面上並沒有另外一個手動觸發的按鈕。

## 欄位定義

### 回測請求（`items[]`）

| Field | Type/Role | Rule |
|---|---|---|
| `stockId` | 股票代號 | 必填；須為主檔中存在的代號（不限已下市）；同一代號可重複出現，只要 `buyDate` 不同 |
| `buyDate` | 進場日 | 必填；掃描回報的進場日，台北日曆日，不得晚於今日、不得缺漏，否則拒絕並說明原因（400，`INVALID_BUY_DATE`）；`(stockId, buyDate)` 組合不得重複 |

### 回測結果明細（`items[]`）

| Field | Type/Role | Rule |
|---|---|---|
| `stockId` / `buyDate` | 回帶識別 | 原樣帶回請求值，順序與請求一致；回應不含 `signalDate` |
| `buyPrice` | 買進價 | 進場日收盤價；進場日無該檔資料或收盤價為 0 時為 null |
| `sellDate` | 賣出日 | 賣出窗口內最高開盤價第一次出現的交易日；無法回測時為 null |
| `sellPrice` | 賣出價 | 賣出窗口（進場日次一交易日起至今日）內開盤價的最大值，開盤價為 0 的列不列入候選；無法回測時為 null |
| `returnPercent` | 報酬率 | `(賣出價−買進價)÷買進價×100`，兩位小數；可為負值，不得夾為 0；無法回測時為 null |
| `profit` | 收益 | `(賣出價−買進價)×1000`，四捨五入至元；可為負值；無法回測時為 null |

### 回測結果彙總

| Field | Type/Role | Rule |
|---|---|---|
| `asOfDate` | 回測迄日 | 今日（台北日曆日） |
| `lotSize` | 每筆股數 | 恆為 1000 |
| `totalCost` | 總成本 | 只計可回測筆的買進成本總和；無可回測標的時為 0 |
| `totalProfit` | 總收益 | 只計可回測筆的收益總和；無可回測標的時為 0 |
| `totalReturnPercent` | 總報酬率 | 以成本加權（總收益÷總成本×100），非各檔算術平均；無可回測標的時為 null，不是 0 |
| `backtestedCount` | 計入彙總筆數 | 即 `sellDate` 非 null 的筆數；與 `items` 長度的差即為無法回測的筆數 |

## 限制條件

- 唯一鍵是 `(stockId, buyDate)` 組合，不是 `stockId`；同一組合重複送出回拒絕並說明原因（400，`DUPLICATE_BACKTEST_ITEM`），不由本端點默默合併。
- 同一買進日只算一筆，即使造成它的是不同策略、甚至不同訊號日：那天只能買進一次。
- 本端點不接受、不依賴任何策略代碼或訊號日；相同 `(stockId, buyDate)` 不論來自哪個型態，回應完全相同。
- 買進日由請求指定，本端點不推算、也不知道任何型態規則。
- 買進價恆取收盤價，賣出窗口恆從進場日次一交易日起算，避免用未來才會出現的價格挑股票。
- 三種情形判定為無法回測（進場日之後無交易日資料、進場日當天無該檔資料列、進場日收盤價為 0），該筆仍出現在 `items` 中但完全不計入總成本與總收益，且不得回錯誤。
- 負的報酬率與收益必須如實回報，不得夾為 0、不得改成不賣出、不得改挑別的日子。
- 價格為原始成交價，未經除權息還原；不計任何交易成本；不做部位管理（無總資金上限、不考慮同時持有幾檔）——這些是已知限制，不在本模組修正。
- `items` 上限 20000 筆（計筆數不計檔數），且不得與掃描端的 `stockIds` 上限（200）共用同一個常數，因為兩者綁的是不同性質的數字。
- 目標清單的價格必須以有界次數的批次查詢取得，不得逐檔各發一次查詢。
- 本端點不寫入任何資料表，也不建立任何進度或併發鎖記錄。

## 跨主題規則

- 買進日（`buyDate`）由掃描端認定並回報（上漲支撐為 D+2、其餘型態等於訊號日），本端點原樣採用、不重新推算，避免出現兩份互相對不起來的型態規則（見 strategy-scan.md）。
- 錯誤碼 `TOO_MANY_STOCKS` 與 `UNKNOWN_STOCK_ID` 沿用掃描端已定義的同名代碼與回應形狀，但沿用的只是錯誤碼，門檻值（本端點 20000 筆、掃描端 200 檔）各自獨立，不得共用（見 strategy-scan.md）。
- 代號存在性檢查不篩是否已下市，已下市股票照常可回測，與掃描端允許指定已下市股票一致（見 strategy-scan.md）。
- 停牌日在行情表中不存在列（不得補零），賣出候選與買進價因此自然排除停牌日（見 stock-price-ingestion.md）。

## API 清單

| Method | Path | 用途 | 送審分類 |
|---|---|---|---|
| POST | /api/strategies/backtest | 依指定的股票與進場日清單，計算每筆的買賣結果與整份清單的總報酬 | Direct（純查詢／即時運算，不寫入任何資料，無需送審） |
