# 策略命中回測 API

策略命中回測 API 把一份掃描命中清單換算成「如果依進場日買進，到今天為止最好能賣在哪裡」的結果，且收益與報酬率是扣除交易成本之後的淨值。這是一個純查詢／純運算功能：只讀取既有的每日股價，不做任何型態判定、不抓取任何外部資料，也不落地任何回測結果，每次呼叫都重新計算。買進日一律採用呼叫端提供、也就是掃描回報的進場日，本功能不重新推算進場日；賣出邏輯固定為「買進日之後至今日為止最高的開盤價」，扣除手續費與證交稅之後回報逐筆與彙總的報酬率與收益，且不涉及送審或核准流程。

## 欄位定義

**回測請求（`items[]`）**

| Field | Type/Role | Rule |
|---|---|---|
| stockId | 股票代號 | 必填；須為主檔中存在的代號（不限已下市）；同一代號可重複出現，只要買進日不同 |
| buyDate | 進場日 | 必填；掃描回報的進場日，台北日曆日，不得晚於今日、不得缺漏；`(stockId, buyDate)` 組合不得重複 |

**回測結果明細（`items[]`）**

| Field | Type/Role | Rule |
|---|---|---|
| stockId／buyDate | 回帶識別 | 原樣帶回請求值，順序與請求一致；回應不含訊號日欄位——訊號日只是顯示資訊，不參與回測計算 |
| buyPrice | 買進價 | 進場日的收盤價；進場日無該檔資料或收盤價為 0 時為 null |
| sellDate | 賣出日 | 賣出窗口內最高開盤價第一次出現的交易日；無法回測時為 null |
| sellPrice | 賣出價 | 賣出窗口（進場日次一交易日起至今日）內開盤價的最大值，開盤價記錄為 0 的列不列入候選；無法回測時為 null |
| buyFee | 買進手續費 | 買進金額 × 0.1425%，無條件捨去至元；買進價為 null 時為 null |
| sellFee | 賣出手續費 | 賣出金額 × 0.1425%，無條件捨去至元；無法回測時為 null |
| sellTax | 證交稅 | 賣出金額 × 0.3%，無條件捨去至元，只在賣出時收取；無法回測時為 null |
| cost | 成本 | 買進金額加上買進手續費；買進價為 null 時為 null；即使該筆最終賣不掉，只要有買進價就算得出成本，但不計入總成本 |
| returnPercent | 報酬率 | 收益 ÷ 成本 × 100，兩位小數；可為負值，不得夾為 0；無法回測時為 null |
| profit | 收益 | 賣出金額扣除賣出手續費、證交稅與成本後的淨額，以元為單位的整數；可為負值；無法回測時為 null |

**回測結果彙總**

| Field | Type/Role | Rule |
|---|---|---|
| asOfDate | 回測迄日 | 今日（台北日曆日） |
| lotSize | 每筆股數 | 恆為 1000；回報它是為了讓呼叫端不必自己知道這個約定就能解釋收益的單位 |
| feeRatePercent | 手續費率 | 恆為 0.1425（百分比），理由同 lotSize |
| taxRatePercent | 證交稅率 | 恆為 0.3（百分比），理由同 lotSize |
| totalCost | 總成本 | 只計可回測筆的成本（含買進手續費）總和；無可回測標的時為 0 |
| totalProfit | 總收益 | 只計可回測筆的收益（已扣手續費與證交稅）總和；無可回測標的時為 0 |
| totalReturnPercent | 總報酬率 | 以成本加權（總收益 ÷ 總成本 × 100），非各檔算術平均；無可回測標的時為 null，不是 0 |
| backtestedCount | 計入彙總筆數 | 即賣出日非 null 的筆數；與 `items` 長度的差即為無法回測的筆數 |

## 限制條件

- 唯一鍵是 `(stockId, buyDate)` 組合，不是 `stockId`；同一組合重複送出即拒絕，不由本功能默默合併。
- 同一買進日只算一筆，即使造成它的是不同策略、甚至不同訊號日：那天只能買進一次。
- 本功能不接受、不依賴任何策略代碼或訊號日；相同 `(stockId, buyDate)` 不論來自哪個型態，回應完全相同。
- 買進日由請求指定，本功能不推算、也不知道任何型態規則。
- 買進價恆取收盤價，賣出窗口恆從進場日的**次一交易日**起算（因為買在買進日收盤，當日開盤在那之前就已經過去），避免用未來才會出現的價格挑股票；其必然副作用是**買進日就是最後一個交易日時，該筆沒有任何可賣出的日子**。
- 三種情形判定為無法回測（進場日之後無交易日資料、進場日當天無該檔資料列、進場日收盤價為 0），該筆仍出現在結果清單中但完全不計入總成本與總收益，且不會讓整次呼叫回傳錯誤。
- 負的報酬率與收益必須如實回報，不得夾為 0、不得改成不賣出、不得改挑別的日子；**賣出價與買進價相同時收益仍為負值**（因為仍要付兩次手續費與一次證交稅），不得顯示為 0。
- **手續費率不打任何券商折扣，也不設最低收費**（因此一筆手續費可以低於 20 元）；**證交稅一律以 0.3% 計算，不依標的種類區分**。
- **三項成本各自無條件捨去至元後才相加，不是先加總再捨去**，且須以精確十進位運算，不得用二進位浮點數計算，否則可能少算 1 元且無從解釋。
- **成本計入買進手續費**，作為報酬率分母的一部分，讓報酬率與收益在同一列上可互相驗算。
- 已知限制三項，須明白告知呼叫端：**價格為原始成交價，未經除權息還原**（有除權息事件的標的，回測報酬率會系統性偏低）；**只計手續費與證交稅，不計滑價**；**不做部位管理**（不考慮總資金上限、不考慮同時持有幾檔、不考慮先賣先買）。
- `items` 上限 20000 筆（計的是筆數，不是檔數），且**不得與掃描端的股票數上限（200）共用同一個常數**——兩者綁的是不同性質的數字，各自因不同理由變動。
- **目標清單的價格必須以有界次數的批次查詢取得，不得逐檔各發一次查詢。**
- **本功能不寫入任何資料表，也不建立任何進度或併發鎖記錄。**

## 跨主題規則

- 買進日完全採用掃描回報的進場日（上漲支撐為 D+2、三個法人籌碼型態與 MACD／KDJ 兩個技術指標型態為訊號日的下一個交易日、其餘型態等於訊號日），本功能原樣採用、不重新推算，避免出現兩份互相對不起來的型態規則（見 `strategy-scan.md`）。
- 錯誤碼 `TOO_MANY_STOCKS` 與 `UNKNOWN_STOCK_ID` 沿用掃描端已定義的同名代碼與回應形狀，但沿用的只是錯誤碼，門檻值（本端點 20000 筆、掃描端 200 檔）各自獨立，不得共用（見 `strategy-scan.md`）。
- 代號存在性檢查不篩是否已下市，已下市股票照常可回測，與掃描端允許指定已下市股票一致（見 `strategy-scan.md`）。
- 買進價與賣出價皆取自既有的每日股價，並沿用同一套「成交價記錄為 0 代表當日未成交」的判讀方式，停牌造成的缺列同樣自然不會被選為賣出日；除權息也未做還原，是全系統一致的股價記錄方式所致（見 `stock-price-ingestion.md`）。
