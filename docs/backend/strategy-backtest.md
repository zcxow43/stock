# 策略命中回測 API

這支 API 把掃描得到的命中清單換算成「如果當時買了，到今天為止最好能賣在哪裡」的結果。呼叫端逐筆送來股票代號與買進日，買進日由掃描回報，這支 API 不自行推算，也不判定任何型態。系統以買進日的開盤價買進。賣出則在買進日的次一交易日起、到今天為止的期間內，挑開盤價最高的那天。買進日若是該檔最新的交易日，期間內沒有任何可賣出的日子，這一筆不算無法回測，而是以買進日的開盤價賣出（賣出日等於買進日、賣出價等於買進價），照常扣手續費與證交稅並計入彙總。這是使用者 2026-10-11 的決定，代價是這類筆的報酬率只剩手續費與稅，是約 -0.58% 的小幅負值。整支 API 是即時讀取既有行情後重新計算，不寫入任何資料、不需送審，結果也不保存。只有「買進日當天沒有該檔行情」與「買進日開盤價為 0」兩種情形無法回測，這兩種仍會列在結果中但不計入彙總，其他錯誤（清單為空、超量、代號不存在、重複、買進日不合法）一律拒絕並說明原因（400）。

## 欄位定義

**回測請求筆（每一筆一個買進日）**

| Field | Type/Role | Rule |
|---|---|---|
| `items` | 清單，必填 | 至少一筆，上限 20000 筆。上限計的是筆數，不是檔數，由掃描可能產出的規模決定，不與掃描的「指定股票 200 檔」共用 |
| `items[].stockId` | 文字，必填 | 股票代號，必須是股票主檔中存在的代號。已下市的股票也可回測。同一代號可出現多次，只要買進日不同 |
| `items[].buyDate` | 日期，必填 | 該筆的買進日，原樣採用掃描回報的進場日（十二個型態皆為確認完成日之後的下一個交易日）。不得缺漏，不得晚於今日（台北日曆日） |
| 策略代碼、訊號日 | 不接受 | 請求與回應都不含這兩項，訊號日只是畫面顯示資訊，不參與計算 |

**回測結果筆（每一筆請求對應一筆結果）**

| Field | Type/Role | Rule |
|---|---|---|
| `stockId`、`buyDate` | 識別 | 原樣帶回請求內容 |
| `buyPrice` | 數字，可空 | 買進日的開盤價。買進日當天沒有該檔行情，或開盤價為 0 時為空 |
| `sellDate` | 日期，可空 | 賣出期間內最高開盤價第一次出現的交易日。期間內沒有可賣出的交易日時等於買進日。無法回測時為空 |
| `sellPrice` | 數字，可空 | 賣出期間內最高的開盤價。期間內沒有可賣出的交易日時等於買進價。無法回測時為空 |
| `buyFee` | 整數（元），可空 | 買進手續費：買進價 ×1000 股 ×0.1425%，無條件捨去至元。無法回測時為空 |
| `sellFee` | 整數（元），可空 | 賣出手續費：賣出價 ×1000 股 ×0.1425%，無條件捨去至元。無法回測時為空 |
| `sellTax` | 整數（元），可空 | 證交稅：賣出價 ×1000 股 ×0.3%，無條件捨去至元，只在賣出時收。無法回測時為空 |
| `cost` | 整數（元），可空 | 成本：買進價 ×1000 股 ＋ 買進手續費。無法回測時為空 |
| `profit` | 整數（元），可空 | 收益：賣出價 ×1000 股 － 賣出手續費 － 證交稅 － 成本。可為負值。無法回測時為空 |
| `returnPercent` | 數字（%），可空 | 收益 ÷ 成本 ×100，四捨五入至小數第二位。可為負值。無法回測時為空 |

買得進去的筆一律有完整結果，所以買進價與賣出日永遠同時有值或同時為空。回應不另加欄位標示「以買進日開盤價賣出」的情形，因為賣出日等於買進日已足以說明。

**回測彙總（整份清單一份）**

| Field | Type/Role | Rule |
|---|---|---|
| `asOfDate` | 日期 | 本次回測的期間迄日，即今日（台北日曆日） |
| `lotSize` | 整數 | 每筆的股數，固定為 1000（1 張） |
| `feeRatePercent` | 數字 | 手續費率，固定為 0.1425 |
| `taxRatePercent` | 數字 | 證交稅率，固定為 0.3 |
| `totalCost` | 數字 | 所有可回測筆的成本總和。沒有可回測筆時為 0 |
| `totalProfit` | 數字 | 所有可回測筆的收益總和。沒有可回測筆時為 0 |
| `totalReturnPercent` | 數字（%），可空 | 總收益 ÷ 總成本 ×100，兩位小數，是以成本加權的結果，不是各筆報酬率的平均。沒有可回測筆時為空，不是 0 |
| `backtestedCount` | 整數 | 實際計入彙總的筆數。它與結果清單筆數的差，就是無法回測的筆數 |
| `items` | 清單 | 逐筆結果，順序與請求完全一致 |

## 限制條件

- **買進價**固定為買進日的開盤價，不用收盤價。
- **賣出期間**從買進日的次一交易日起算，買進日自己的開盤價不納入賣出候選。
- 只要買進之後還有任何可賣出的交易日，賣出日就一定晚於買進日。
- 賣出期間內開盤價為 0 的日子不是行情，不列入賣出候選。期間內只剩這類日子時，視同期間為空。
- 最高開盤價在多天出現相同數值時，取最早那一天為賣出日。
- 只有兩種情形無法回測：買進日當天沒有該檔行情，或買進日開盤價為 0。這兩種筆仍會出現在結果中，各欄位為空，不計入總成本、總收益與 `backtestedCount`，也不會讓整次請求失敗。
- 買進日是該檔最新交易日的筆照常回測，不屬於無法回測，並計入彙總。
- 「以買進日開盤價賣出」只在賣出期間為空時啟用，不是賣出價的下限。期間內只要有一個可賣出的日子，就取期間內最高開盤價，即使它低於買進價。
- 賣出價低於買進價是正常結果，負報酬必須如實回報，不得改成 0、不賣出或改挑別的日子。
- 賣出價等於買進價時收益也是負的（例：買賣皆 1,150 元，收益 -6,726），因為仍要付兩次手續費與一次證交稅。
- 手續費不打折、無最低收費，證交稅一律 0.3%，不分標的種類。三項費用各自捨去後再相加，並以精確十進位運算。
- 每一筆固定 1 張。一檔股票每有一個相異買進日就是獨立一筆，各自計入彙總，彼此的賣出期間互不影響。
- `(stockId, buyDate)` 的組合不得重複，即使是不同策略或不同訊號日造成的。重複時直接拒絕，不默默合併。
- 價格是未經除權息還原的原始價。買進後若遇除權息，報酬率會系統性偏低。
- 只計手續費與證交稅，不計滑價，也不做資金或持有檔數的限制。
- 本 API 不保存結果，每次呼叫重新計算。「以買進日開盤價賣出」的結果是暫時的：該檔多出交易日後再回測，就回到一般規則。
- 價格查詢必須以整份清單為條件做批次查詢，不得逐檔各查一次。

## 跨主題規則

- 買進日完全由掃描回報決定，十二個型態皆為確認完成日之後的下一個交易日。回測只負責「那一天開盤買進」，不做型態區分，也不自行推算進場日（見 strategy-scan.md）。
- 「代號不存在」與「筆數超過上限」沿用掃描已定的同名錯誤代碼與回應形狀，但上限數字各自獨立。掃描綁的是使用者手打的清單（200 檔），回測綁的是掃描產出的命中規模（20000 筆），兩者不得共用同一個常數（見 strategy-scan.md）。
- 無法回測的標的必須留在結果中並讓呼叫端看得出來，不得悄悄漏掉。這與掃描「不得因資料不足把標的拿掉」是同一條原則（見 strategy-scan.md）。
- 代號是否存在不過濾是否仍在上市，因此已下市股票可照常回測，與掃描允許指定已下市股票一致（見 strategy-scan.md）。
- 回測只讀已入庫的每日行情，不對外抓資料。行情中以 0 記錄的「該日沒有成交」不得成為買點或賣點，停牌日沒有資料列，所以自然不會成為賣出日（見 stock-price-ingestion.md）。
- 價格查詢遇到空清單時，必須略過查詢，不把空集合交給資料庫，與行情模組的規定相同（見 stock-price-ingestion.md）。
- 本 API 不寫入任何資料，也不建立同步進度，因此與價格回補、指標重建的併發鎖互不影響。回補進行中仍可正常回測（見 stock-price-ingestion.md）。
